# Перевод PDF в Markdown

[Инструкция агента](Агент/PDF_TO_MD_AGENT.md) описывает перевод и сверку таблиц, чисел, сносок и графики по физическим страницам. [Реестр отчётов](../00_Отчёты/Реестр_отчётов.csv) содержит исходные ссылки и пути Markdown.

## Локальный запуск

Нужен Python 3.11 или новее. Команды выполняются из корня репозитория.

~~~sh
python3 -m venv .venv
. .venv/bin/activate
agent="Основной_проект/01_Перевод_PDF_в_Markdown/Агент"
python -m pip install -r "$agent/requirements.txt"
python "$agent/convert_pdf.py" pdf "вход.pdf" "черновик.md"
python "$agent/convert_pdf.py" corpus \
  --corpus "Основной_проект" \
  --pdf-dir "/путь/к/PDF" \
  --out "/путь/к/новой/копии" \
  --require-pdfs
~~~

В папке источников каждому PDF нужно имя из реестра, например `NORN-2023-ОУР.pdf`. Из архивов берите сам отчёт. Режим `pdf` создаёт черновик с исходными строками и предупреждениями о слабом слое. Сканированные области нужно распознать и сверить отдельно.

Режим `corpus` сохраняет в выходную папку обновлённые Markdown, реестр и, при полном прогоне, метаданные корпуса. Он использует существующие таблицы и OCR, сверяет исходный текстовый слой постранично и проверяет отображение целых документов. В `conversion_run.json` перечислены ограничения, контрольные суммы и страницы для последующей сверки. Для запуска по отдельным отчётам укажите `--only ID1 ID2`. Если убрать `--require-pdfs`, для отсутствующего исходника будет проверена только структура Markdown, с явной отметкой.

Проверка таблиц сопоставляет Markdown с сеткой PDF, сверяет числа и записывает страницы с исправлениями в `table_repair_pages`. Повторяющиеся полностью пустые столбцы между последовательными годами убираются. Геометрически неоднозначные таблицы отмечаются в `review_queue`. При переносе результата сохраняйте соседние папки `assets` с графикой из оригиналов.

Дополнительная сверка числовых ячеек выполняется в режиме `corpus`. Она ищет заголовки и строки по координатам текстового слоя. Если сразу после показателя идёт столбец «Ед. изм.», агент сверяет его текст и положение по PDF перед сравнением чисел. Для простой HTML-таблицы агент автоматически исправляет перестановку, если исходная строка найдена однозначно, состав значений совпал, контрольная строка подтвердила сетку и повторное чтение областей PDF подтвердило правку. Знаки, сноски и разметка соседних ячеек сохраняются. Таблицы Markdown проверяются с сохранением исходной разметки. Сложные сетки и остальные расхождения переходят на ручную сверку.

В `conversion_run.json` у каждого отчёта поля `table_cells_compared` и `table_cells_repaired` показывают число сопоставленных и переставленных ячеек. В `table_cell_review` есть физическая страница, номер таблицы и результаты. Для найденного расхождения указываются строка, столбец, оба значения и прямоугольник в координатах PDF. У сложной или неоднозначной таблицы записывается причина. Протокол включает только автоматически проверенную область. Для заявления о полной смысловой сверке используется отдельный журнал ручной проверки.

Для регрессионных тестов из корня репозитория используйте `python -m unittest discover -s "$agent"`. Чтобы включить тесты на реальных отчётах СИБУРа, ММК, «Акрона» и ЛУКОЙЛа, задайте `GREENWASHING_TEST_PDF_DIR` с путём к папке исходных PDF из команды выше.
