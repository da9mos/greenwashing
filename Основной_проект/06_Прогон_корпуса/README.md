# Полный прогон корпуса

Поручение от 20.11.2026: обработать все 92 отчёта по 30 компаниям и получить сводку каждой компании. [Текущий статус](status.json), [реестр отчётов и прогресса](Сводка_прогона.csv).

## Принцип работы

1. Зафиксировать неизменяемые версии 92 Markdown, физические страницы, SHA-256 исходника и профиля 3.1. Повреждённые таблицы, числа, графики и сомнительный OCR требуют сверки с исходным PDF. Структурная проверка не закрывает смысловую.
2. Обойти все 3 716 партий по четыре страницы. Для каждого блока сохранить extracted / excluded / pending с основанием. Сохранять обязательства, результаты, декларации, показатели и отрицательные сведения. Тип и E/S/G размечать независимо. Для чисел обязательны единицы, период, периметр и точные цитаты. Непрочитанное не исключать.
3. Проверить ответы контрактом профиля 3.1, а затем независимо проверить смысл, пропуски, таблицы и графики по PDF. Наличие coverage не является измеренной полнотой. Исходные ответы и последующие ревизии сохранять раздельно. Ручная контрольная разметка и метрики требуют отдельного эталона; согласие моделей его не заменяет.
4. Для каждого заявления выполнить реальный поиск подтверждений и противоречий. Сопоставлять юридическое лицо, год, метрику и периметр; сохранять прочитанные источники и даты. Отсутствие данных не означает ложь. По обещаниям различать существование обещания, исполнение и ненаступивший срок. Использовать действующий агент фактчекинга.
5. После обработки отчётов собрать один Excel на компанию, отдельный лист и CSV на отчёт и сводку компании: охват страниц, E/S/G, типы, проверенные результаты и открытые вопросы. Открытые проверки блокируют финальную приёмку, но не исчезают из рабочего черновика.

## Исполнение и возобновление

`python3 run_corpus.py` перечитывает и заново проверяет сохранённые ответы локального worker, затем обновляет сводки всех 30 компаний. Исторические пилоты не перезаписываются. Оригинальные принятые ответы остаются в существующем кэше.

В производных сводках ID заявления получает префикс партии. Это устраняет совпадения локальных номеров между партиями без удаления заявлений и без изменения цитат. `id_provenance` сохраняет исходный ID и партию; модельные оригиналы не меняются. Одна партия Мечела уже содержит совпадающие с другой партией ID, поэтому такая привязка обязательна при сквозной сборке.

`python3 run_corpus.py --run --watch` продолжает **этап извлечения** локально, с сохранением прогресса после партии. Подготовленная очередь не зависит от SSH-сервера. Для исключения конкуренции при запуске ставится пауза прежнего SSH-worker. Используется текущая авторизация Codex, без нового платного API. При сетевой ошибке действует обратная задержка до пяти минут; отклонённые ответы сохраняются для разбора и не становятся готовыми.

После извлечения контроллер явно останавливается на следующем этапе: независимая сверка по PDF и действующий фактчекинг. Этот контроллер не объявляет автоматически выполненными проверку PDF, веб-поиск, человеческую разметку или конечную приёмку. В текущем запуске он реализует первую массовую стадию общего плана.

Локальное управление: `~/.local/state/sber-corpus-run-20261120/current.json`, `runner.log`, `attempts/`. Файл `STOP` в этой папке прекращает новые итерации после текущей партии. Файл `~/.local/state/sber-esg-worker/PAUSED` оставляет прежний SSH-worker на паузе; автоматическое удаление этой паузы в контроллер не заложено, чтобы после сбоя не запустились два исполнителя одного кэша.

## Когда отчёт считается готовым

Все партии и блоки учтены; не осталось неразобранных исходников, графиков и числового контекста; выполнена независимая сверка; у каждого заявления есть реальный результат фактчекинга либо явно обоснованный незакрытый статус; экспорт совпадает с проверенными данными. Рабочий черновик с открытыми вопросами публикуется с этим ограничением. Итоговую полноту и качество не подменяем количеством строк или зелёными тестами кода.
