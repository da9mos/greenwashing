# Агент ESG: научно обоснованный профиль3.1

18.11.2026. [Методика и определения](Методика_выявления_ESG_v3_1.md) · [Инструкция модели](agent/esg_agent_v3_1.md) · [Правила и источники](agent/decision_rules_v3_1.json) · [21 тема](agent/taxonomy_v3_1.csv).

Сначала прочитайте методику: она объясняет, что является ESG-высказыванием, границы E/S/G, разницу предмета и действующего лица, научные основания и выбранные проектом правила. Полный реестр включает показатели, отрицательные результаты и декларации. Поиск и E/S/G отделены от проверки истинности.

## Запуск

Распакуйте весь комплект. Из его корня:

```sh
python scripts/esg_agent_v3_1.py prepare report.md --report-id GAZP-2023-ЭО --out work/GAZP-2023-ЭО
python scripts/esg_agent_v3_1.py model-files --work work/GAZP-2023-ЭО --out work/GAZP-2023-ЭО/model_inputs
python scripts/esg_agent_v3_1.py check --work work/GAZP-2023-ЭО responses/GAZP-2023-ЭО_b0001.json
python scripts/esg_agent_v3_1.py export --work work/GAZP-2023-ЭО --responses responses/*.json --out exports/GAZP-2023-ЭО
```

Команды выше выполняются из папки `02_Аналитика_заявлений/Агент`. Актуальные Markdown и их хеши берите из `00_Отчёты/Реестр_отчётов.csv`. Для таблиц и битых фрагментов нужна сверка по PDF.

Для извлечения передайте модели только три файла из `model_inputs` и JSON конкретной партии. В этих трёх файлах есть инструкция, готовые правила и темы. Библиографию оставляйте в методике для человека. Скрипт сам не вызывает модель. Размер партии по умолчанию 4 страницы и соседний контекст. Флаг `--pages-per-batch` меняет размер без обрезки текста. Служебное вступление MD сохраняется отдельно.

Партии привязаны к хешу промпта. После обновления инструкции создайте новый рабочий каталог. Для повторной проверки старых ответов используйте прежнюю версию инструкции по исходному пути из manifest.

## Что требуется в результате модели

Для каждого заявления нужны цитаты, тип, основная буква и тема, числовой контекст, а также decision с субъектом, пропозицией, ESG-объектом, ID правил включения и классификации, дополнительными буквами и статусом неоднозначности. Для исключённого блока нужно правило исключения. Неизвестное остаётся pending.

Модель указывает ID применённых правил. При экспорте скрипт сам подставляет ключи научных оснований в `source_refs` из локального реестра правил. Старые ответы с этим полем сохраняют совместимость. Истинность объяснения остаётся задачей независимой смысловой проверки.

CSV профиля 3.1 сохраняют поля прежней выгрузки и добавляют ID отчёта, SHA-256 исходного Markdown, тип источника, количественные поля и массив дословных опор `evidence_json`. Кодировка UTF-8 с BOM, разделитель `;`. Для штатного `prepare` этапа 03 передавайте `claims.json`. Для чтения другой моделью можно передать `claims.csv` с инструкцией читать `evidence_json` как JSON внутри ячейки и сохранять пустые поля как неизвестные.

Незавершённые блоки/изображения/числовой контекст или неоднозначная буква блокируют обычный экспорт. `--allow-partial` создаёт только черновик `_draft`. Недостающие партии не разрешаются даже этим флагом.

## Проверки и границы

- 67 тестов в папке `Агент/tests`. Это тесты программной механики, точных цитат, числовых опор, выгрузки и входного комплекта модели.
- Реальный MD Газпрома2023:84 страницы,1237 блоков,21 партия подготовлены и привязаны к хешам методики/таксономии. Смысловое извлечение всех блоков не выполнено.
- `examples/profile3_1/source.md` и `response.json` — шесть искусственных блоков для демонстрации: E, S, G, G+E+S, неопределённая самопохвала и обычная выручка. Это авторский разбор Codex, не независимый эталон и не оценка точности.
- На трёх отложенных страницах сравнили старый и обновлённый промпты с одной моделью и одинаковыми изображениями и Markdown. Обе версии покрыли содержание 167 единиц. Прирост точности и скорости генерации не подтверждён. [Условия и результаты](../Проверка_агента_2026-11-22/Сравнение/Отчёт_сравнения.md)

## Проверка примера после распаковки

```sh
python scripts/esg_agent_v3_1.py prepare examples/profile3_1/source.md --report-id DEMO-2024 --out example_work --pages-per-batch 1
python scripts/esg_agent_v3_1.py check --work example_work examples/profile3_1/response.json
python scripts/esg_agent_v3_1.py export --work example_work --responses examples/profile3_1/response.json --out example_export --allow-partial
```

Ожидается4 заявления,1 pending-блок,1 исключение. Без флага экспорт отклоняется. Изображение/таблица без установленного контекста не считаются обработанными только по факту существования файла.

Контракт хранения JSON - `esg-extraction-3.0`, методический профиль - `decision_profile_version=3.1`. Скрипт3.1 использует функции `esg_agent_v3.py`, поэтому оба файла нужны.
