# Полное извлечение ESG: профиль v3

**Актуальное уточнение методики3.1:** [определения, научные основания и запуск](README_v3_1.md). Прежние версии и их метрики сохранены отдельно.

18.11.2026. Разработан на основе коммита `5597472` основного репозитория. Рабочая ветка `codex/esg-complete-v3-20261118`.

## Назначение

Из полного MD или JSONL страниц собрать реестр ESG-заявлений и разложить их по типу (обязательство, результат, декларация), букве E/S/G и одной из 21 темы проекта. Предусмотрены дополнительные буквы. Подготовка и проверка выполняются скриптом, смысловое извлечение — моделью в сессии; ключ API не требуется.

Отличие от v2: показатели воздействия и численности, строки таблиц, короткие утверждения, нарушения и отрицательные результаты входят в состав извлечения. Нет словарного фильтра и квоты на компанию. Заголовки и таблицы рассматриваются с контекстом, неизвестное остаётся открытым.

## Этапы

1. Подготовить источник: PDF → MD с маркерами физических страниц и изображениями. Если используется текст v4, таблицы и повреждённые области должны проверяться по PDF; JSONL не восстанавливает их автоматически.
2. `prepare`: зафиксировать хеши входа, промпта и таксономии, сформировать все блоки и партии.
3. Модель читает `agent/esg_agent_v3.md` и каждую партию, сохраняет отдельный JSON. Исходные ответы не редактировать задним числом; исправленный проход — новая папка.
4. `check`: сверить цитаты, типы, темы, числовой контекст и учёт всех блоков. Исправление исходника или промпта требует нового пакета.
5. Независимый проход повторно рассматривает все блоки, в том числе исключённые: согласие и полный реестр сами по себе не являются измерением полноты. Для оценки нужен отдельный полностью размеченный набор по расширенному определению.
6. `export`: общий реестр, E/S/G, ссылки на исходные блоки и список незавершённых мест. Частичный результат выдаётся явно как черновик.
7. Проверка истинности выполняется отдельно по доказательствам. Сохранять ID заявления и его доказательства при передаче в агент оценки; повторно искать заявления внутри оценки не требуется.

## Что обеспечивает программа

Проверяет заявленный охват всех входных блоков, состав партий, неизменность исходника и инструкций, совпадение цитат, соответствие теме таксономии и наличие контекста чисел. Неполный пакет или незавершённые блоки не должны незаметно становиться итоговым результатом.

Что программа не доказывает: правильность E/S/G, полноту смыслового извлечения, соответствие исходному PDF и истинность утверждений. `md_only` — проверка цитаты по MD. `needs_pdf_review` — требуется обращение к оригиналу. Отсутствие pending ещё не является сертификатом качества.

## Совместимость и метрики

Старые промпты v1/v2, 928 заявлений, 811 предложений эталона, сохранённые LLM-ответы и командный кодбук остаются в своих версиях. Новый профиль не переписывает решения команды. 99,4% по букве на распознанных заявлениях v2 и recall 87,6% нельзя переносить на v3. Для старого эталона часть новых числовых утверждений является ожидаемым расхождением определения.

Научная база и темы: [анализ статей](Анализ_научных_статей_ESG.md), [таксономия](agent/taxonomy.csv), [новая инструкция](agent/esg_agent_v3.md). Различие трёх этапов — обнаружение / E,S,G / фактическая оценка — сохранено.

Результат этого изменения — работающий инструмент и инструкция. Массовое модельное извлечение всех заявлений 92 отчётов этим изменением не объявляется выполненным.

## Запуск из корня репозитория

```sh
python "Агент определитель ESG + анализ статей/scripts/esg_agent_v3.py" prepare report.md --report-id GAZP-2023-ЭО --out work_v3/GAZP-2023-ЭО
python "Агент определитель ESG + анализ статей/scripts/esg_agent_v3.py" check --work work_v3/GAZP-2023-ЭО responses_v3/GAZP-2023-ЭО_b0001.json
python "Агент определитель ESG + анализ статей/scripts/esg_agent_v3.py" export --work work_v3/GAZP-2023-ЭО --responses responses_v3/*.json --out exports_v3/GAZP-2023-ЭО
```

Ответы готовит модель в отдельных проходах по партиям; `prepare` их не создаёт. По умолчанию партия включает 4 страницы и соседние страницы контекста, настройка `--pages-per-batch`. Слишком большие страницы/таблицы не обрезаются: оператор должен выбрать посильный объём, сохранив весь target. Все MD/JSONL страницы должны идти подряд от 1; TXT номера являются сегментами текста, не физическими страницами PDF.

Если есть нерешённые блоки или заявления, экспорт без `--allow-partial` завершается ошибкой. С флагом создаётся каталог с суффиксом `_draft`, статусом partial и точным числом открытых мест. Все партии всё равно обязательны: флаг не разрешает потерять целые партии.

Состав экспорта: `claims.csv`, `E.csv`, `S.csv`, `G.csv`, `claims.json` со всеми цитатами и числовым контекстом, `coverage.csv`, `summary.json`. Основные буквы делят уникальные ID; дополнительные буквы пересекаются и не суммируются с количеством уникальных заявлений.

Второй независимый смысловой проход и фактчекинг пока выполняются отдельно. CLI не выдаёт автоматическое подтверждение PDF и не содержит модели классификации по ключевым словам.

## Проверено при реализации

45 тестов агента прошли: 18 прежних и 27 новых. На существующем MD Газпрома 2023 (экологический отчёт) подготовлены все 84 страницы: 1 237 блоков, 84 партии по одной странице; каждый целевой блок назначен ровно одной партии. Авторский текст не переписан, служебное вступление сохранено отдельно. Это проверка подготовки и механики, не полный модельный прогон и не сверка PDF. Точность и полнота v3 пока не измерены.
