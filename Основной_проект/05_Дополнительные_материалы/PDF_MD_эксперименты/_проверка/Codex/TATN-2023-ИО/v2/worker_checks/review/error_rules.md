# Подтверждённые классы ошибок и контрольные сценарии

## Управляющий код вместо видимого знака или пробела

Причина: некорректная Unicode-карта встроенного шрифта. Признак: непечатный код в авторском тексте. Действие: посмотреть глиф и соседние слова по оригиналу, определить роль по изображению и координатам; не подставлять букву по смыслу. Приёмка: читаемое представление соответствует виду источника; повреждённый в самом PDF знак явно помечен.

Сценарий: кандидат с управляющим кодом отклоняется; подтверждённый лидер принимается как многоточие; повреждённый исходный глиф получает пометку, а не догадку.

## Графический флажок не входит в текстовый слой

Причина: рамка и отметка нарисованы векторно. Признак: несколько вариантов статуса без текстового указания выбранного. Действие: соотнести каждый флажок и отметку по геометрии с подписью, проверить по изображению. Приёмка: различены выбранный и пустой варианты; сомнительная привязка остаётся pending.

Сценарий: одинаковое оформление всех вариантов отклоняется; подтверждённые ☑/☐ принимаются; неоднозначная геометрия не повышает статус до checked.

## Строка после маркера ошибочно становится надстрочной

Причина: автоматическое сравнение высот стрелки и обычного текста. Признак: длинная фраза целиком внутри sup после маркера. Действие: проверить базовую линию по оригиналу; убрать только ложное надстрочное оформление. Приёмка: текст обычного размера, настоящие сноски сохранены.

Сценарий: длинная надстрочная фраза отклоняется после подтверждения обычной базовой линии; обычный текст принимается; короткий неоднозначный знак проверяется отдельно.

## Таблица теряет названия и связь строк

Причина: названия находятся в логотипах, разделители не совпадают с логическими ячейками. Признак: безымянные серии значений, разрезанный заголовок периода, результат без названия конкурса. Действие: пересобрать весь затронутый объект по оригиналу с проверкой каждой ячейки. Приёмка: каждая серия имеет источник/категорию, период и исходное значение.

Сценарий: числа без источника отклоняются; целиком сверенная таблица принимается; непроверенная принадлежность строки получает пометку.

## Построчное чередование колонок

Причина: сортировка по вертикальной координате при заголовке, перекрывающем несколько колонок. Признак: разрыв фразы строками соседнего абзаца. Действие: установить границы смыслового блока и читать его колонки по оригиналу. Приёмка: абзацы сохранены последовательно, сверены соседние связи; совпадение инвентаря символов недостаточно.

Сценарий: перемежённые абзацы отклоняются; подтверждённый порядок колонок принимается; неустановленный порядок остаётся pending.

## Переносы внутри атрибута URL ломают Markdown с HTML

Причина: адрес аннотации содержит технический перенос строки. Признак: следующие блоки отображаются как буквальный Markdown, хотя файл изображения существует. Действие: удалить пробельное форматирование внутри адреса после проверки исходного атрибута; повторно отрендерить. Приёмка: адрес сохранён, последующие изображения и разметка разбираются.

Сценарий: URL с разрывающим HTML переносом отклоняется; тот же адрес без технических пробелов принимается; сомнительный адрес не дополняется догадкой.
