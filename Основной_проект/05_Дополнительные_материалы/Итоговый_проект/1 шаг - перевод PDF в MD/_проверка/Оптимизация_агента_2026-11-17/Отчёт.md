# Оптимизация инструкции PDF → Markdown

17.11.2026. Оптимизирован комплект первого этапа. Отчёты и инструкции оценки ESG-заявлений не объединяются: у них разные входы, критерии и результаты.

## Решение

Один основной модельный файл PDF_TO_MD_AGENT.md с двумя явно выбранными режимами: перенос DeepSeek и проверка Codex. В модельный запрос попадают основной файл, режим и назначенная исходная страница. Отдельный проход проверки сохранён; самопроверка переводчика его не заменяет.

README и ERROR_RULES перенесены в Справка/. README содержит технический контракт evidence, команды и ограничения обвязки. ERROR_RULES — реестр 24 классов ошибок для сопровождения. Их не нужно целиком передавать в каждом модельном запросе. Для машинного review manifest Codex читает справку по необходимости.

Основной файл сокращён с 39 736 до 18 393 байт, на 53,7%. Это измерение размера текста, а не доказанная экономия токенов, стоимости API или рост точности. Повторы сведены, существенные ограничения сохранены. Полная предыдущая редакция и служебные документы сохранены в before/; frozen, raw и старые кэши не изменялись.

## Почему так

- Начинать с простой схемы и добавлять агентов по доказанной необходимости: [Building effective agents, Anthropic](https://www.anthropic.com/research/building-effective-agents). Генерация и отдельная оценка подходят для задач с ясными критериями; согласие моделей не доказывает истинность
- Короткая рабочая инструкция и загрузка подробностей по необходимости: [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices). Количество Markdown-файлов не равно количеству агентов
- Отбирать нужный контекст: [Effective context engineering](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents). Справочник сопровождения не должен повторять рабочую инструкцию в каждом запросе

Для этого проекта выбран один комплект инструкций на этап с определёнными проходами. Это проектное решение на основе источников, а не требование иметь ровно один файл или один модельный вызов. Код выполняет детерминированные проверки, модель читает сложное содержание. Дополнительный «агент-диспетчер» без необходимости не вводится.

## Что сохранено

Полный обход зон/увеличений с bbox; OCR как подсказка; реквизиты и языковые варианты; границы навигации; числа и сноски; каждая таблица со всеми ячейками и продолжениями; связи графиков, формулы и формы; реальные ссылки/вложения; правильные страницы/якоря; raw и происхождение; адресные исправления; полный компонентный review; реальные evidence; различие checked и partial; переносимость; разрешения и недоступность API; изоляция версий и обязательный пилот до включения в контроллер. Эти группы покрывают 24 класса исходного ERROR_RULES, который сохранён без содержательных изменений.

## Проверки

139 существующих локальных тестов инструментов прошли после восстановления отсутствующих markdown-it-py и beautifulsoup4 в временном каталоге зависимостей. Лог: tests.log. Первый прогон без зависимостей не завершился; это исправленная ошибка среды. Тесты подтверждают программные защиты, а не семантическое качество новой инструкции.

Независимый Codex-проверяющий применил основной файл к физической странице 57 GAZP-2023-ОУР без чтения справки. Визуально проверены четыре таблицы, числовые ячейки/периоды 2021–2023, примечания и пояснения; source.png пиксельно совпал с рендером оригинальной PDF-страницы. Значения 0,173², 76,6² и 1,963 переданы верно в существующем переносе. Полнота отображения и PDF-ссылки остались pending; отсутствие боковой навигации требует явного описания роли. Проверяющий не присвоил full-page checked. Критических проблем применимости инструкции в этом ограниченном сценарии не выявлено.

Проверены относительные ссылки внутри обновлённого комплекта и побайтовая идентичность проектного/общего мастеров. Актуальные ссылки двух входных документов обновлены после переноса справки.
