# Шаг 2. Извлечение ESG-заявлений

## Новая методика v2: тип заявления и E/S/G

Текущая разработка: [инструкция v2](Агент/EXTRACT_AGENT.md), [научное обоснование](Методика_v2/Научное_обоснование.md), [пилот](Пилот_v2/). Каждая запись получает тип и основную E/S/G с дополнительными темами. Числовые показатели включаются с проверяемым контекстом. Незавершённые блоки и спорные записи сохраняются явно.

Скрипт `Агент/extract_esg_v2.py` поддерживает prepare, validate и export CSV/JSON. Человеческая оценка полноты ещё не выполнена. Исторические 708 записей и команды ниже относятся к v1, не к завершённой разметке v2. Старый Excel-сборщик v2 не поддерживает.

17.11.2026 · один экологический отчёт ПАО «Газпром» за 2023 год · 84 PDF-страницы

Этот шаг получает Markdown, извлекает заявления и распределяет их по трём типам. Проверка исполнения, поиск внешних фактов и гринвошинг относятся к следующему шагу.

- [Excel](Пример_Газпром_2023/Газпром_2023_заявления.xlsx)
- [CSV](Пример_Газпром_2023/Газпром_2023_заявления.csv)
- [Инструкция агента](Агент/EXTRACT_AGENT.md)
- [Реестр цитат, страниц, контекстов и оснований типов](Пример_Газпром_2023/claims.json)
- [Протокол проверки](Проверка/Отчёт.md)

В таблицах ровно четыре столбца: **№, Обязательства, Результаты, Декларации**. Одна строка — одно заявление. В соответствующем типу столбце находится текст, два других пусты. Пустоты здесь предусмотрены форматом. Нумерация сквозная, порядок соответствует источнику.

**708 записей: 52 обязательства, 616 результатов, 40 деклараций.** Результат означает сообщение компании о действии, процессе или достижении, включая отрицательную динамику. Этот тип не подтверждает истинность заявления. Голые количественные показатели, оглавление, глоссарий, контакты и речь внешнего аудитора не включены.

Просмотрены все 84 страницы MD. Цитаты проверены по исходным страницам; дополнительно проведена сверка с PDF. Выявленные ошибки переноса исправлены в отдельном рабочем исходнике с журналом замен. Старый MD корпуса сохраняется. Охват проверки PDF и ограничения описаны в протоколе; посимвольная проверка всего отчёта и измеренная полнота поиска не заявляются.

Дословный текст хранится в JSON. В Excel/CSV удалена Markdown-разметка, индексы единиц представлены обычными надстрочными/подстрочными символами, содержательные строки таблиц развёрнуты с исходными заголовками. Зависимые фрагменты списков сопровождаются проверенным контекстом из отчёта. Один пункт, перешедший со страницы 42 на 43, собран из двух отдельно проверенных фрагментов.

## Использование агента с другим отчётом

Передайте Codex [инструкцию](Агент/EXTRACT_AGENT.md) и путь к Markdown следующего отчёта: «Прочитай эту инструкцию, извлеки заявления из указанного отчёта целиком и создай такую же таблицу. Анализ истинности не выполняй».

`Агент/extract_claims.py` готовит пакеты по восемь страниц, валидирует JSON и создаёт CSV. Он не делает смысловую классификацию сам. Смысл выполняет LLM в сессии Codex. `Агент/build_excel.mjs` создаёт XLSX и проверяет все сохранённые ячейки; нужен установленный в среде Codex `@oai/artifact-tool`.

Подробные команды находятся в инструкции. Для имени результата передайте `export --name Название_отчёта_заявления`; иначе имя по умолчанию — «Заявления».

## Повторная проверка текущего примера

Из этой папки:

```bash
python3 Агент/extract_claims.py validate --report '../1 шаг - перевод PDF в MD/Результаты работы/Газпром 2023 - экологический отчёт/report.md' --claims Пример_Газпром_2023/claims.json
python3 Агент/extract_claims.py export --report '../1 шаг - перевод PDF в MD/Результаты работы/Газпром 2023 - экологический отчёт/report.md' --claims Пример_Газпром_2023/claims.json --output Пример_Газпром_2023 --name Газпром_2023_заявления
node Агент/build_excel.mjs Пример_Газпром_2023
python3 -m unittest discover -s Агент -p 'test_*.py' -v
```

Исходные экспериментальные результаты находятся в [историческом репозитории](../../3_итерация/greenwashing/README.md). Пакет с тремя примерами оценки сохранён [отдельно](../2%20этап%20-%20оценка%20заявлений/README.md). Новый шаг не пересчитывает его классы и не меняет совместный Git-репозиторий.

## Продолжение разработки · 17.11.2026

Добавлена команда `merge`: можно сохранять результаты по пакетам и собирать их после завершения отчёта. Пропуски, повторно обработанные страницы, чужой хеш и невалидные цитаты останавливают сборку. Существующий итог не перезаписывается. Формат частей и команда приведены в инструкции агента.

Повторная проверка 708 записей выполнена по текущему исходнику шага 1 с совпадением SHA-256. Путь `Проверка/Рабочий_исходник/report.md` из прежних команд отсутствует; команды выше исправлены на проверенный источник. Это подтверждает цитаты в MD, но не повторную смысловую сверку с PDF.
