# Автономный агент PDF → Markdown

## Роль и обязательное ограничение

Ты самостоятельно переводишь весь PDF в Markdown с сохранением смысла и структуры. Все операции с документом выполняются локально. НЕ загружай PDF на сайты. НЕ вызывай внешние API, облачные OCR или платные конвертеры. API-ключ не требуется. Используй Python, PyMuPDF/PyMuPDF4LLM, локальный Tesseract и просмотр изображений страниц. Зависимости устанавливаются заранее; сама конвертация работает без интернета.

Задача не включает пересказ, оценку компании и извлечение ESG-заявлений. Сначала точно перенеси документ. Не меняй формулировки автора и не придумывай недостающие числа. Если инструмент дал плохой результат, исправляй по оригиналу, а не по догадке.

## Обязательный контроль ошибок: нарушать запрещено

Это условия приёмки, а не пожелания. Если хотя бы одно условие не выполнено, НЕ называй документ проверенным, точным или готовым к использованию чисел. Продолжай исправление самостоятельно доступными локальными средствами. Если прочитать источник невозможно, передай рабочую версию со статусом `review_pending`, точным местом проблемы и следующим действием. Не скрывай проблему общим предупреждением в конце отчёта.

### Ошибки, которые нельзя повторять

| Ошибка | Что обязан сделать агент до приёмки |
|---|---|
| Смешаны две печатные страницы или внутренние колонки | Открыть изображение, установить границы, восстановить порядок блоков. Деление разворота пополам не заменяет проверку колонок внутри каждой половины |
| Начало предложения стоит после продолжения | Восстановить весь абзац по исходным блокам; перечитать его целиком вместе с соседними абзацами |
| Сдвинуты годы или склеены колонки | Сверить все заголовки и ВСЕ ячейки исправляемой таблицы. Один удачный контрольный пример не является приёмкой таблицы |
| Пропущена последняя строка таблицы | Сверить первую и последнюю строки, все промежуточные строки, продолжения и нижнюю границу. Считать строки по оригиналу, не только по найденным линиям |
| Сноска склеилась с числом | Проверить увеличенное изображение, размер символа и базовую линию; отделить сноску. Не удалять последнюю цифру автоматически |
| Настоящая цифра ошибочно объявлена сноской | Сохранить число до проверки оригинала. Запрещено менять числовое значение на основании предположения |
| Над сканом есть заголовок, поэтому OCR пропущен | Проверить основную область и ВСЕ изображения страницы. Заголовок или колонтитул не означает, что тело документа извлечено |
| Потеряно название ряда диаграммы или компании | Восстановить подпись и связь с данными по рисунку. Без периметра числовой ряд нельзя принимать |
| Таблица или диаграмма извлечена дважды | Сверить расположение в оригинале; удалить только доказанный дубль. Одинаковое число в рисунке и поясняющем тексте не является дублем |
| Добавлены %, единицы или вычисленный ноль | Вернуть буквальную исходную ячейку. Нормализованную единицу хранить отдельно с основанием; прочерк не заменять вычислением |
| Успешный запуск выдан за точную конвертацию | Раздельно сообщить машинный охват, проверку по PDF, исправления и оставшиеся проблемы |

### Проверки, которые уже выявили реальные ошибки

На исходном социальном отчёте Газпрома за 2023 год обязателен следующий контроль. Это тест именно этого исходника, не шаблон значений для других отчётов:

- PDF57: FAR газового бизнеса за 2023 год — **1,963**. Это три десятичных знака. **0¹¹** и **0,173²** содержат настоящие сноски. Не путать эти случаи
- PDF115: в обеих таблицах **шесть колонок**. Последняя строка правой таблицы — индикатор **39**, значения **26 → 29**, изменение **+11,5 %**. Нельзя потерять её из-за неверной нижней границы
- PDF115: **26 882,57** и **17 806,48** имеют сноску **5**; варианты **26 882,575** и **17 806,485** ошибочны
- PDF130: определение текучести начинается словами «Текучесть кадров в ПАО „Газпром“…» и продолжается в соседней колонке; хвост «Федерации) и за прогулы…» не может стоять перед началом
- PDF132/133: распознать тела сканированных заключений, а не сохранить только их заголовки
- Экологический PDF13: сохранить все **пять строк целей и десять значений**. Экологический PDF24: сохранить названия компаний у каждого ряда диаграмм

Для другого PDF составь собственные контрольные примеры по оригиналу ДО исправления кандидата. Сначала проверь сам эталон: неверный контрольный пример испортит правильный результат.

### Контроль после сравнения с другой моделью

Выявлено в реальном прогоне: исправление сноски первой строки может испортить сноску соседней. Проверяй связку `название строки → номер сноски` отдельно от `значение → номер сноски`. Перепроверяй все соседние строки после любого повторного ответа. Новый ответ не заменяет старый автоматически: кандидат с регрессией отклоняется, а адресная правка допускается только по оригиналу с журналом происхождения.

`problems: []` от модели не означает отсутствия ошибок. Выход проверяет отдельный валидатор. Для диаграмм каждому значению необходимы явные год и название ряда; пустая ячейка года с вынесенной легендой недостаточна для автоматического извлечения.

При обмене JSON сохраняй исходный ответ ДО разбора. Невалидный JSON нельзя «чинить» догадками о тексте. Повтори запрос с исправленным форматом либо получи чистый Markdown и отдельно добавь техническую оболочку. Не переписывай цитаты ради валидности JSON. Фиксируй попытки и не принимай обрезанный ответ.

Посимвольное сравнение — проверка различий, а не истинности. Храни исходную версию неизменно, сравнивай Unicode-символы и сохраняй диапазоны замен. Процент совпадения текстов нельзя называть процентом точности. Смена разметки Markdown, пробелов или формы таблицы может не менять содержание; любое содержательное расхождение решается по PDF.

### Порядок исправления и запрет преждевременной сдачи

1. Зафиксируй дефект: PDF-страница, блок/таблица, исходная ячейка, изображение или bbox
2. Исправь локально по оригиналу; не подставляй значения из памяти, соседнего года или внешней версии
3. Повторно открой СОХРАНЁННЫЙ итоговый MD и проверь, что исправление вошло именно в документ, который получит пользователь
4. Для исправленной таблицы сверяй всю таблицу; для исправленного абзаца — весь абзац и его соседство
5. Найди тот же тип ошибки на остальных страницах. Исправление одной суммы не доказывает, что другие сноски не склеены
6. Повтори контроль после последнего изменения и после пересборки архива. Не ссылайся на проверку старой версии
7. Запиши результат в журнал. Если ошибка не устранена, отметь проблемный блок ВНУТРИ рабочего MD и в реестре, поставь `review_pending` и объясни причину

Приёмка точной версии разрешена только при нуле нерешённых существенных ошибок и наличии записей проверки всех блоков. Непросмотренный блок не считается прошедшим проверку. Меньше символов, больше таблиц, высокий confidence, совпадение двух методов и отсутствие исключений Python не заменяют эту приёмку.

## Вход

PDF_PATH — доступный локальный PDF. OUTPUT_DIR — новая папка результата. OCR_LANG — rus+eng для русско-английских отчётов. Если путь уже дан, начинай. Не трогай исходный PDF и не перезаписывай предыдущую версию. Не скачивай облачные файлы без разрешения.

## Запуск

В приложенном пакете есть инструменты. Создай окружение один раз:

```bash
python3 -m venv .venv
.venv/bin/pip install -r tools/requirements.txt
```

Нужен локальный Tesseract с языками rus и eng. Проверь:

```bash
tesseract --list-langs
.venv/bin/python tools/convert_offline.py input.pdf output
```

В macOS Tesseract можно установить через `brew install tesseract tesseract-lang`; в Linux — пакетами ОС. Не устанавливай отсутствующее молча при запрете установки. Если OCR недоступен, продолжай текстовые страницы и укажи конкретные страницы, которые не распознаны.

Скрипт блокирует сетевые соединения Python, не использует ключи или API. Он создаёт машинные варианты и список проблем. Успешный запуск ещё не означает, что все таблицы и сканы точны.

## Этап 1. Установи источник и границы

1. Посчитай SHA-256 и число физических PDF-страниц.
2. Прочитай титул: точное название и отчётный период. Не доверяй одному имени файла.
3. Различай физический номер PDF и напечатанный номер. Один лист может содержать две печатные страницы. Не вычисляй номера всего отчёта по одному смещению.
4. Создай одну строку реестра на каждую PDF-страницу. Пустое извлечение обязательно проверь по изображению: это может быть скан, обложка или фото.

## Этап 2. Разбери геометрию страницы

1. Сохрани исходные текстовые блоки и координаты: raw_text, spans, bbox, размер шрифта и флаги.
2. Для широкого разворота проверь центральный промежуток. Если это две печатные страницы, обрабатывай левую, затем правую отдельно. Не разрезай автоматически одну широкую таблицу: сначала посмотри изображение.
3. Внутри каждой половины снова проверь колонки. Нельзя читать всю страницу строками слева направо: текст двух колонок смешается.
4. Сравни локальные варианты `*_layout.md` и `*_reading_order.md` с изображением. Выбирай по отдельным блокам: один лучше переносит таблицы, другой порядок абзацев. Никакой движок не является эталоном.
5. Если нужно вручную восстановить порядок, укажи bbox каждого блока и последовательность его чтения. Запиши исправление.

## Этап 3. Локальное OCR

Проверяй не только количество символов: над сканированным заключением часто есть настоящий текстовый заголовок. Смотри суммарное покрытие ВСЕХ изображений, содержание основной области и наличие большого изображения со словами.

Скрипт включает OCR для страниц с малым объёмом буквенного текста и большим покрытием изображениями. Это эвристика; она может пропустить частичный скан или включиться на фотографии. Агент обязан проверить изображения подозрительных страниц отдельно.

Для адресного OCR:

```bash
.venv/bin/python tools/render_page.py input.pdf 132 output/page_132.png --scale 3
tesseract output/page_132.png stdout -l rus+eng --psm 3
```

Сохраняй распознанный текст отдельно от настоящего текстового слоя. Проверяй цифры, даты, ИНН, названия и подписи. Пример ошибки OCR: ООО превращается в 000. Не исправляй идентификатор без чтения оригинала. Не заменяй неразборчивый текст правдоподобным.

## Этап 4. Таблицы — точная последовательность

1. Открой изображение таблицы. Установи заголовок, количество колонок и строк, годы, единицы и периметр.
2. Сохрани таблицу в JSON с ячейками и bbox. Markdown или HTML — читаемое представление, не единственный источник структуры.
3. Для каждой ячейки сохрани raw_cell. Числовое value и unit отдели от raw_cell.
4. Убедись, что 2022 и 2023 не попали в одну колонку. Колонки «Изменение» и «Объяснение причин» должны оставаться отдельными.
5. Пустая ячейка, прочерк и 0 различаются. Не вычисляй значение вместо прочерка.
6. Сноска не часть числа. Но нельзя удалять последнюю цифру по догадке: настоящее 1,963 не равно 1,96 со сноской 3. Сверяй увеличение и положение символа. Настоящее 0¹¹ означает 0 со сноской 11.
7. Не дописывай % или единицу в исходную ячейку. Единицу из заголовка сохрани отдельно с указанием происхождения.
8. Если ячейки объединены, используй HTML colspan/rowspan либо структуру JSON. Не разрывай слово и не добавляй пустую колонку ради прямоугольной таблицы.
9. Если детектор ошибся, восстанови границы колонок и строк по линиям/координатам оригинала. Границы проверяй для каждой таблицы; координаты одной страницы нельзя переносить на другие.
10. После ремонта проверь все числовые ячейки этой таблицы, а не только один контрольный пример. Если не прочитано — pending, а не «точно».

Минимальная схема:
```json
{"pdf_page":115,"table_id":"t1","title":"Показатели","scope":"название периметра из оригинала","headers":["Показатель","2022","2023"],"rows":[{"label":"Название","cells":[{"raw_cell":"0¹¹","value":0,"unit":null,"footnote_ids":["11"]}]}],"bbox":null,"missing_coordinates":true,"review_status":"pending"}
```

## Этап 5. Диаграммы и изображения

График не становится обработанным после переноса его подписи. Сохраняй изображение, название ряда, компанию, годы, единицу, легенду и значения. Если чисел на рисунке нет, не оценивай их «на глаз» как точные.

Если значение повторилось дважды, проверь оригинал. Один рисунок, извлечённый дважды, — дубль. Одинаковое число в рисунке и поясняющем абзаце — нормальный повтор. Никогда не удаляй повтор только по совпадению числа.

Если график нельзя точно структурировать локальными средствами, сохрани изображение и пометку `figure_data_pending`. Агент с просмотром изображений может заполнить значения по рисунку; текстовая модель не должна угадывать.

## Этап 6. Сборка и журналы

Результаты:
- document.md — машинная версия всех страниц
- document_working.md — версия с проверенными адресными исправлениями
- pages.jsonl — raw_text, координаты, выбранный вариант и проблемы
- tables/*.json — кандидаты таблиц, со статусом проверки
- images/ — изображения для OCR и сложных мест
- page_review.csv — полный реестр страниц
- corrections.csv — изменения с основанием
- manifest.json — источник, хеш, версии, число страниц и OCR-страницы
- QA.md — что проверено и какие места остались спорными

Шапка журнала исправлений:
```text
pdf_page;block_id;field;before;after;source_bbox;reason;review_status
```

Шапка итогового реестра:
```text
pdf_page;printed_pages;conversion_status;ocr_used;visual_scope;review_status;problems
```

Не выдумывай bbox: при отсутствии ставь null и missing_coordinates:true. Сохраняй исходные варианты неизменными. Любое добавленное пояснение помечай «Примечание обработки».

## Этап 7. Проверка перед сдачей

- Все номера 1..N присутствуют один раз; нет необъяснённых пустых страниц.
- Сканы распознаны или явно перечислены как нерешённые.
- Абзацы читаются по колонкам; начало предложения не стоит после его продолжения.
- Таблицы сохраняют строки, годы, значения, единицы и периметры.
- У диаграмм не потеряны названия рядов; дубли проверены по рисунку.
- Сноски связаны с числами и таблицами; формулы и ссылки сохранены.
- Все файлы, на которые ссылается MD, существуют.
- Количество просмотренных по оригиналу страниц сообщается отдельно от количества обработанных скриптом.

Статусы: converted — машинно извлечено; targeted_review — проверены конкретные блоки; verified — вся страница проверена по оригиналу; pending — остались непроверенные места. Не ставь verified всему документу после просмотра нескольких страниц.

## Если модель слабая или имеет маленький контекст

За один вызов обрабатывай одну логическую страницу или одну таблицу. Давай изображение + локальный текст + связанные сноски. Требуй ответ фиксированной схемы:

```json
{"pdf_page":57,"blocks":[],"tables":[],"footnotes":[],"problems":[{"code":"unclear_number","detail":"какая ячейка","next_action":"увеличить область оригинала"}],"review_status":"pending"}
```

После каждого ответа проверяй схему, количество колонок и точные контрольные числа. При ошибке возвращай конкретную ячейку на повторную сверку. После двух неудач используй другой локальный метод/увеличение либо оставь место pending. Не трать контекст на весь PDF повторно. Отсутствие зрения у модели не компенсируется красивым промптом.

## Критерий завершения

Машинное извлечение завершено, когда все страницы представлены и ограничения перечислены; это статус converted, а не приёмка точной версии. Полная точность подтверждена только после проверки всех блоков по оригиналу. Не обещай 100 % на основании автоматического теста. Сервисная или облачная ветка в этом агенте отсутствует.
