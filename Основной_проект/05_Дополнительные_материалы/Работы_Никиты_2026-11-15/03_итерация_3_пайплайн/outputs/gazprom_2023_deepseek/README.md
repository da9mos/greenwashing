# Газпром 2023: DeepSeek против локальной конвертации

[Открыть наглядное сравнение](review.html) · [Обновлённый агент](PDF_TO_MD_AGENT_UPDATED.md) · [Профиль DeepSeek](DEEPSEEK_PDF_AGENT.md) · [Реестр страниц](page_comparison.csv)

## Что сделано

Полностью обработаны два тех же исходных PDF: социальный 136 страниц и экологический 84 страницы, всего 220. DeepSeek-flash получил изображения исходных страниц, а не локальный MD в качестве подсказки. Широкие развороты передавались двумя изображениями. Предыдущие локальные MD сохранены в baseline неизменными; совпадение хешей с исходной версией проверено после обработки.

Первый независимый результат — social_deepseek_v1.md / environment_deepseek_v1.md. Выбранные ответы после адресной переработки — social_deepseek_selected.md / environment_deepseek_selected.md. Нет автоматического правила «любая v2 лучше v1»: выбор записан в selection.json.

## Посимвольное сравнение

Для каждой из 220 страниц сохранены два точных протокола Unicode: локальная версия → первый DeepSeek и локальная версия → выбранный DeepSeek. Всего 440 JSON в char_diff. Каждый содержит позиции и содержимое вставок, удалений и замен. Обратная сборка по всем 440 протоколам воспроизвела конечный текст без расхождений.

Это сравнение транскрипций, а не признание локального MD истиной. Пробелы, Markdown-разметка, колонтитулы, порядок блоков и OCR дают различия даже при сохранении содержания. Символьное расстояние и числовые токены используются как сигналы проверки, а не процент точности.

В 187 страницах различаются мультимножества числовых токенов. Это НЕ 187 доказанных числовых ошибок: в локальном варианте встречаются склейки/пропуски, иначе представлены годы и сноски, а сканы распознаны разными способами. Нельзя автоматически выбрать победителя по этому числу. Отдельно проведены адресные проверки исходных изображений — см. INDEPENDENT_QA.md и CHART_QA.md.

## Сравнение качества по проверенным участкам

DeepSeek лучше прежней локальной версии восстановил порядок колонок, структуру сложной таблицы115 и текст сканированных заключений. На115 сохранены денежные сноски5, индикатор39 и нули/прочерки. Экологические таблицы13/40 и проверенные графики передали значения корректно; на76проверены14ячеек Scope1/Scope2/CH4, на79—проверенные регистрационные номера и дата.

Это адресная проверка, а не полная экспертная приёмка каждой буквы всех 220 страниц. Графическая подпись на экологической79в текстовый Markdown не перенесена; исходное изображение доступно в интерфейсе. Рабочие документы не объявляются безусловно точными. Для дальнейшего фактчекинга каждое используемое заявление сверяется с оригиналом отдельно.

## Отображение

review.html содержит переключение всех 220 страниц, обе версии рядом, строковый diff, исходный Markdown, ссылки на точный символьный протокол и изображения оригинала. Все стили/данные встроены, CDN не используется; папка images должна лежать рядом.

Проверка реального рендера выполняется в headless Chrome. Результаты — display_check.json и visual_check. Посмотрены ключевые снимки на desktop 1440px и mobile 390px; это проверка интерфейса, а не всех символов на каждом скриншоте.

## Доступ и расходы

DeepSeek вызывается по отдельному явно разрешённому API-подключению. Ключ только в Keychain/памяти процесса; ни в промпты, ни в пакет не включён. Базовый локальный конвертер остаётся без сетевых запросов и не стал отправлять документы автоматически.

Получено 223 валидных ответа (220 основных +3 повторных); ещё 2 попытки имели ошибочный JSON. По валидным ответам 491201 входной и322901 выходной токен. Это не точный биллинговый итог: в него не включены форматноошибочные ответы. Баланс не пополнялся.

У первой форматной ошибки85сырой ответ не был сохранён начальным раннером; осталась запись ошибки. Это недостаток протоколирования, исправленный в раннере. Вторая ошибочная оболочка и ответ восстановления сохранены. Не заявляем полное наличие сырых ответов всех попыток.

## Файлы и воспроизведение

system_v1.txt/system_v2.txt — точные операционные инструкции; v1/v2 — ответы с хешами изображений и usage; source_checked — адресная правка по источнику; selection.json — решения приёмки; rejected_candidates.json — отвергнутая регрессия; corrections.csv — журнал; verification.json — технические проверки.

Инструкция для следующих прогонов — PDF_TO_MD_AGENT_UPDATED.md. Промпт для API короче полной инструкции, его версия зафиксирована. Это изменение правил и проверок, а не дообучение весов модели.


Команды воспроизведения из корня Системы (зависимости — tools/requirements.txt):

```bash
python3 11_Проект_Сбер/3_итерация/greenwashing/03_итерация_3_пайплайн/outputs/gazprom_2023_deepseek/tools/run_deepseek.py --workers 8
python3 11_Проект_Сбер/3_итерация/greenwashing/03_итерация_3_пайплайн/outputs/gazprom_2023_deepseek/tools/compare.py
python3 11_Проект_Сбер/3_итерация/greenwashing/03_итерация_3_пайплайн/outputs/gazprom_2023_deepseek/tools/build_review.py
```

Первый запуск вызывает API и расходует баланс; существующие ответы используются из кэша. При адресном повторе создаётся отдельный кандидат, решение выбора принимается через selection.json. Протокол отказов и повторов нельзя очищать, чтобы скрыть неудачные попытки.
