# Независимая проверка локального PDF→MD

15.11.2026. Проверяющий не выполнял сетевых запросов, не запускал облачные API и не использовал их ответы для принятия новых блоков. Основание — локальные пробы разделения разворотов и изображения исходных PDF, просмотренные ранее. Сравнение с предыдущим локальным PyMuPDF4LLM допустимо; совпадение двух результатов не доказывает правильность.

## Пробы разделения разворотов

### Социальный PDF57

Разделение на две печатные страницы убрало смешение левых и правых таблиц разворота. Числа `0,173` со сноской2, FAR`1,963`, нули со сноской11 сохранены. Важно:1,963 — настоящее число.

Абзац о FAR в правой половине теперь следует в правильном порядке. Но слева после таблицы травматизма два соседних текстовых столбца ещё смешаны: «Коэффициент частоты травматизма количества пострадавших. Коэффициент…попритяжести…». Этому блоку нужен `review_pending`, а не общий `source_checked` страницы.

### Социальный PDF115

Главное улучшение: самостоятельные таблицы двух печатных страниц больше не смешаны в одну строку. Однако левая таблица имеет пять столбцов вместо шести: значение2022попало в ячейку названия («Компании газового бизнеса<br>0,08»), шапка разбита на фрагменты слов. Числа0,102;0,323;0,191;1,963;12,309 видны, но автоматическое извлечение по номерам колонок небезопасно. Нужна адресная реконструкция по геометрии ячеек и исходному изображению.

### Социальный PDF130

Числовая часть таблицы сохранилась, многоуровневая шапка всё ещё разбита. Определение текучести кадров выведено в неправильном порядке: сначала конец «Федерации) и за прогулы…», затем начало «Текучесть кадров…(п.3ст.77Трудового кодекса Российской». Разделение разворота пополам не решило порядок двух колонок внутри печатной страницы.

## Правила принятия локального результата

1. Различать физический разворот, отдельную печатную страницу и колонки внутри неё; порядок чтения проверять на каждом уровне.
2. Не считать страницу принятой только по сохранности пяти чисел. Структура, единицы, периметры и поясняющая проза проверяются отдельно.
3. Распознавание скана локальным Tesseract отмечать движком, языком, страницей и областью; исходный скан сохранять. Цифры из заключения/реквизиты не превращать в ESG-результаты без контекста.
4. Для повреждённой таблицы с шестью исходными колонками контролировать шесть отдельных смысловых полей, а не только одинаковое число pipe-разделителей.
5. Сохранять машинный MD неизменённым; рабочие коррекции журналировать с координатами/изображением и основанием.
6. Полная техническая обработка страниц не равна визуальной проверке всех страниц, полному извлечению заявлений или их фактчекингу. Не обещать100%точность.

Полный новый локальный экспорт на момент этой записи ещё ожидался; окончательные результаты ниже дополняются только после его появления.

### Критический пропуск OCR, передан на исправление

В первом полном проходе социальныеPDF132/133остались114/105символов: заголовки и номера страниц, без текста заключений. Выбранlayout,manifest`ocr_pages=[]`. Значит вставленные сканы не распознаны, хотя полный файл технически обработан.

В коде первичной версии площадь изображения рассчитывается только для первогоPDF-image, который может быть небольшим логотипом. Этого недостаточно для определения скана. Требуется анализ всех областей изображений/объединённого покрытия, объёма содержательного текста без колонтитулов и адресная проверка сканов132/133. Замечание передано автору; последующая версия проверяется отдельно ниже.

### Полностью локальное выполнение

В просмотренном инструменте нет клиентов облачногоAPI; Python-соединения блокируются черезsocket, вызовы распознавания — локальныйsubprocess`tesseract -l rus+eng`. Установка зависимостей может требовать сеть отдельно; в ходе проверяемой конвертации облачныйсервис не нужен. Это обзор кода и артефактов, не независимый системный перехват всего сетевого трафика.
