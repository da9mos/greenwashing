# Агент точного перевода PDF в Markdown

## Задание

Преобразуй весь указанный PDF в читаемый Markdown, сохранив содержание, порядок чтения, таблицы, годы, единицы и сноски. Для нескольких PDF обработай каждый отдельно, затем составь общий реестр. Работай по шагам ниже. Не пересказывай текст. Не меняй числа и термины ради красивого оформления. Не объявляй результат точным только потому, что скрипт завершился.

Вход: путь к PDF, выходная папка, разрешён ли облачный сервис, предел расходов, язык. Если путь и задача уже известны, начинай. При отсутствии облачного доступа выполни локальную часть, зафиксируй ограничение. Не выдумывай облачный запуск. Секреты получай из переменной окружения или скрытого ввода; не записывай их в MD, код, логи или команды.

## Что выдать

- `document.md`: рабочая версия всего документа с маркерами каждой PDF-страницы
- `pages.jsonl`: постраничные записи и координаты источника
- `tables/`: таблицы с ячейками, заголовками, единицами и сносками
- `manifest.json`: хеш исходника, число страниц, движки, версии, конфигурации и ID облачных заданий
- `page_review.csv`: одна строка на каждую страницу, ни одной пропущенной
- `corrections.csv`: что исправлено, где и на каком основании
- `QA.md`: результаты проверок и конкретные нерешённые места

Сохраняй необработанные результаты каждого движка отдельно. `document.md` не заменяет исходный PDF. Если остались спорные страницы, укажи `review_pending`; не ставь `verified` всему документу.

## Фиксированные поля: не переименовывай

`page_review.csv`:
```text
report_id;pdf_page;printed_pages;local_status;cloud_status;comparison_status;visual_scope;review_status;problems;chosen_source
```

`corrections.csv`:
```text
report_id;pdf_page;block_id;field;before;after;source_basis;reviewer
```

Пример проблемы:
```json
{"pdf_page":24,"block_id":"chart-3","status":"review_pending","problems":[{"code":"missing_scope","detail":"В таблице нет названия компании","action":"Открыть исходную диаграмму и восстановить подпись"}]}
```

Допустимые статусы перечислены в шаге7. `bbox` — реальные координаты источника; если их нет, ставь null и missing_coordinates:true. Не придумывай координаты. Числа110и111в примере — две печатные страницы одного листа PDF.

## 1. Проверь исходник

1. Проверь доступность локального файла. Не скачивай облачные файлы без разрешения; не обходи ограничения рабочего пространства.
2. Открой PDF, посчитай страницы и SHA-256. Сохрани точное название с титула и отчётный период. Имя файла может быть неточным.
3. Проверь страницы разных типов: обычный текст, разворот, таблица, график, скан, сноски.
4. Различай `pdf_page` (от 1) и `printed_pages`. Один лист PDF может содержать две печатные страницы. Если печатный номер не установлен, оставь null. Не вычисляй весь документ по смещению одного листа.
5. Пустая строка извлечения не означает пустую страницу: проверь изображение. Обложку, фото и скан различай явно.

## 2. Сделай независимый локальный проход

Извлеки текст с учётом геометрии блоков и таблиц, например PyMuPDF4LLM. Сохрани результат ДО чтения облачного результата. Зафиксируй хеши. Это локальный проход с библиотекой, а не ручная транскрипция всех страниц.

Работай по одной странице или ограниченными партиями. Сохраняй результат сразу, чтобы восстановиться после ошибки. Не пересылай модели весь большой отчёт каждый раз.

Для каждой страницы сохрани raw_text и блоки/слова с bbox. Markdown добавь с маркером:

```markdown
<!-- pdf_page: 57; printed_pages: 110–111 -->
## PDF-страница 57 · печатные страницы 110–111

Текст первой колонки, затем следующей…
```

Порядок чтения определяй по исходной странице. `sort=True` и сортировка всех строк по высоте сами по себе не решают многоколоночную вёрстку. OCR используй для сканов/повреждённого текстового слоя; не заменяй исправный текст OCR без причины.

## 3. Сделай облачный проход, если он разрешён

Сначала проверь доступ и предполагаемый расход. Не покупай кредиты автоматически. Отправляй исходный PDF, а не испорченный локальный MD. Для сложных таблиц разумная исходная проба — LlamaParse Agentic; лучший режим выбирай по тесту конкретного документа.

Сохрани запрос без ключа, ID задания и полный ответ с `markdown`, `items`, `metadata`, `text`. Дождись `job.status == COMPLETED`; наличие ID не означает готовый результат. При тайм-ауте продолжай опрос того же ID, не создавай новое платное задание. Уточняй текущий API по официальной документации.

Сверь список номеров: ровно 1..N, без пропусков и дублей. Не путай нулевую индексацию локальной библиотеки и номера API. Проверяй `page.success`, ошибки и наличие данных. Уверенность сервиса — только сигнал, не доказательство правильности.

## 4. Правила таблиц — выполнять буквально

Для каждой таблицы сохраняй:

```json
{"table_id":"report-p57-t4","pdf_page":57,"printed_pages":[110,111],"title":"FAR","scope":"Компании газового бизнеса","headers":["2021","2022","2023"],"rows":[{"label":"Компании газового бизнеса","cells":[{"raw_cell":"1,963","value":1.963,"year":2023,"unit":null,"footnote_ids":[]}]}],"source_bbox":null,"missing_coordinates":true,"review_status":"pending"}
```

- Каждая цифра остаётся связана с названием строки, годом, единицей и периметром.
- Не объединяй «Изменение» и «Объяснение причин» в одну колонку. Число и комментарий — разные поля.
- Многоуровневый заголовок раскрывай в однозначные подписи колонок; исходный заголовок сохраняй отдельно.
- Удаляй пустую колонку только после проверки, что она пустая во всех строках и в оригинале нет отдельной колонки. Записывай исправление.
- Для диаграммы, переведённой в таблицу, обязательно сохраняй название серии/компании. Анонимная таблица «Год | Значение» непригодна для фактчекинга.
- Если одно изображение/таблица распознано дважды, убери повтор только после проверки оригинала. Повтор в приложении или на другой странице не считается дублем автоматически.
- `0`, `—`, пустая ячейка и «нет данных» различаются. Не подставляй нули вместо пропусков.
- `0¹¹` означает значение 0 со сноской 11. Но `1,963` может быть настоящим числом. Проверяй увеличенное изображение, размер шрифта и базовую линию; не удаляй последнюю цифру по догадке.
- `%` и `п. п.` различаются. Не дописывай единицу в raw_cell. Единицу из шапки сохраняй в unit с указанием источника.
- Разрывы страниц и продолжения таблиц связывай только при совпадении шапки, единиц и периметра. Сохраняй все исходные страницы.
- Для объединённых ячеек допустим HTML. Не ломай структуру ради обязательной pipe-таблицы Markdown.

## 5. Сравни все страницы

Составь таблицу: pdf_page, наличие локального/облачного текста, число строк таблиц, числовые различия, порядок блоков, обнаруженные проблемы, выбранный вариант, проверка по оригиналу.

Автоматически ищи пропуски, повторные блоки, оборванные таблицы, сдвиги годов и разницу числовых токенов. Эти проверки формируют очередь просмотра. Количество символов, похожесть текстов и совпадение двух движков НЕ являются процентом точности.

Сначала проверяй страницы с числами, таблицами, графиками, сканами, разными результатами и низкой уверенностью. Проверяй каждую страницу, на которой основан исследовательский вывод. Не заменяй просмотр спорных мест средним показателем качества.

При расхождении открой оригинал с достаточным увеличением и запиши решение. Если не можешь прочесть, оставь `[НЕРАЗБОРЧИВО: PDF-страница …, область …]`, сохрани изображение и статус pending. Ничего не угадывай.

## 6. Собери рабочий MD

Выбери лучший блок по оригиналу. Не смешивай результаты без журнала происхождения. Удали повторяющееся меню из текста только если сохранил raw и проверил, что это навигация, а не содержание.

Сохраняй названия, формулы, ссылки, сноски и подписи рисунков. Поправка OCR по оригиналу допустима; литературная редактура цитат запрещена. У добавленного пояснения пиши «Примечание обработки», чтобы его нельзя было принять за слова автора.

Если график не удалось точно преобразовать, сохрани его изображение и подпись со статусом непроверенных данных. Не объявляй график обработанным на основании одной подписи.

## 7. Завершение и проверка

Проверь последовательно:

1. Источник и SHA-256 установлены; все N страниц представлены ровно один раз.
2. Нет неотмеченных пустых страниц и ошибок выполнения.
3. Таблицы имеют подписи, периметры, годы, единицы и ссылки на сноски.
4. Все выявленные существенные расхождения исправлены либо явно перечислены в QA.md.
5. В сверенных блоках нет текста, придуманного моделью вместо источника; для непросмотренных блоков сохранён pending. Не объявляй отсутствие выдумок во всём документе без такой проверки.
6. Исправления чисел, единиц и периметров имеют запись в corrections.csv.
7. Ссылки на изображения и файлы существуют.
8. В итогах указано, сколько страниц обработано машинно, сколько сверено визуально и сколько ожидает решения. Не объединяй эти числа.

Статусы: `converted` — извлечено; `compared` — сопоставлено; `source_checked` — проверено по PDF; `review_pending` — есть нерешённое место. Готовность конвертации не означает проверку истинности заявлений компании.

## Работа с ограниченной моделью

За один вызов давай одну страницу/одну таблицу, исходное изображение и связанные сноски. Передавай таблицу соседней страницы только для её продолжения. Требуй JSON фиксированной схемы: page, blocks, tables, footnotes, problems. Не проси одновременно конвертировать отчёт, оценивать гринвошинг и писать выводы.

После каждого ответа запускай механическую проверку схемы и контрольных чисел. При ошибке верни конкретную ячейку и требование сверить оригинал. После двух неудач передай страницу на ручную/более сильную проверку, оставив pending. Один хороший пример не доказывает качество всех страниц. Эта инструкция не гарантирует одинаковый результат разных моделей; его нужно измерять.

## Воспроизводимый запуск приложенных инструментов

```bash
python3 -m venv .venv
.venv/bin/pip install -r tools/requirements.txt
.venv/bin/python tools/local_convert.py input.pdf output
.venv/bin/python tools/cloud_convert.py input.pdf output --tier agentic
.venv/bin/python tools/compare_report.py output
.venv/bin/python tools/render_page.py input.pdf 57 output/page_57.png --scale 3
```

Ключ вводится скрыто либо берётся из LLAMA_CLOUD_API_KEY. Скрипты создают local_pages/*.json и *.md, локальный manifest, cloud/result.json, два исходных MD и page_comparison.csv. Сборка pages.jsonl, page_review.csv, журналов исправлений и source-checked таблиц — отдельная работа агента по этой инструкции. Скрипты выполняют два машинных прохода; они НЕ заменяют шаги 4–7 и не создают автоматически источникопроверенный document.md. Проверенная версия библиотеки в этом опыте: pymupdf4llm 2.1. При другой версии повтори пробу.

Для примера прочитай README.md, INDEPENDENT_QA.md и page_comparison.csv рядом. За 2023 год Газпрома представлены два документа: социальный 136 страниц и экологический 84; это границы корпуса опыта, не утверждение о всех возможных публикациях компании за год.
