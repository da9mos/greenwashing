# Газпром: проба извлечения PDF и исправления процесса

15.11.2026. Проверен исходный PDF социальной отчётности за 2023 год из библиотеки РСПП: 136 PDF-страниц. SHA-256 и ссылка в pilot_manifest.json. На четырёх страницах (50, 57, 115, 130) выполнено локальное извлечение PyMuPDF в обычном порядке и с sort=True. Три сложные страницы (57, 115, 130) просмотрены визуально.

## Что действительно протестировано

Локальное извлечение и его риски. Облачный LlamaParse теперь запущен: четыре страницы в Cost-effective и Agentic, оба задания COMPLETED. Результаты в cloud_test. Оценка базовой стоимости — 12+40=52 кредита; фактическое списание и остаток баланса ответ API не показал. Кредиты не покупались, настройки оплаты не изменялись. Ключ использован только в памяти процесса, в проект не записан.

## Реальные ошибки и риски

1. PDF-страница 57 содержит печатные страницы 110–111. Одна ссылка на номер без указания системы нумерации неоднозначна.
2. ИСПРАВЛЕНИЕ собственного первоначального вывода: FAR равен 1,963. Цифра 3 не является сноской. Увеличение оригинала и координаты/размер шрифта подтверждают число; оба облачных режима передали его правильно. Реальные контрольные сноски: 0¹¹ и 0,173². Недостаточное увеличение при визуальной сверке привело к ошибочному тестовому эталону; он исправлен с объяснением.
3. На странице 115 текучесть: 5,9% за 2022 и 6,7% за 2023, изменение +0,8 п. п. Процентные пункты нельзя заменить процентами. Таблица содержит разные периметры, их нельзя объединять.
4. На странице 130 определения периметра идут рядом с таблицей, на соседней печатной странице разворота. Привязывать ближайшее определение ко всем таблицам автоматически нельзя.
5. Название файла ОУР не описывает документ точно: титул — отчёт о социальной деятельности. Разделы экологии присутствуют, поэтому отчёт нельзя объявлять исключительно социальным; полноту экологического корпуса нужно проверять отдельно.
6. Побайтное отличие нового текста от кэша само по себе не доказывает ухудшение: различаются пробелы и порядок блоков. Размер текста и sort=True также не являются метриками качества.

## Как обрабатывать дальше

- Реестр исходников: компания, точное название, отчётный период, дата публикации, вид отчёта, URL и хеш. Проверять наличие экологических приложений отдельно.
- Основной слой: исходные страницы и структурированный JSON с координатами, таблицами, сносками и обеими нумерациями. Markdown — представление для чтения; он один не сохраняет все связи.
- Проба LlamaParse: те же четыре страницы через Cost-effective и Agentic; не более 52 базовых кредитов за оба прохода (4×3+4×10), без допопций. Не запускать весь корпус заранее. Перед отправкой сверить фактические текущие расценки и лимит аккаунта.
- Проверять числовые ячейки по acceptance_cases.json и оригиналу; годы, единицы, периметры и сноски обязательны. Критическая ошибка в числе/годе/единице означает непригодность результата для автоматического вывода, даже если текст выглядит красиво.
- Страницы с низким качеством направлять на повторную обработку и визуальную сверку; хранить причину и выбранный результат. OCR применять по необходимости.
- Извлекать все три типа заявлений по кодбуку; отдельно просматривать таблицы. Числовые строки становятся отдельными проверяемыми заявлениями только с подписью показателя, периметром и годом.
- Полноту считать по реестру всех страниц: обработана/проверена/повторить, плюс контроль разделов и таблиц. Полнота извлечения оценивается отдельно от истинности заявлений.
- Для каждого заявления раздельно хранить: проверку точности цитаты, тип заявления, статус фактчекинга, доказательства и флаг риска. Надпись «проверено по странице» не означает «подтверждено фактами».
