# Правило связной цитаты для вывода

Поручение: в Excel заявление должно читаться как точная связная цитата с достаточным контекстом. Атомарный смысл оценки сохраняется отдельно; разбиение фактов на атомы не отменяется.

## Интерфейс

Новые генерации проектного `esg_agent_v3_1.md` обязаны дать у каждого claim:

```json
{
  "presentation_quote": "Одна непрерывная цитата из исходного блока",
  "presentation_block_id": "REPORT:p38:b4"
}
```

Для исторических данных эта пара опциональна. Отсутствие обоих полей сохраняет совместимость аналитического контракта, но означает `unprepared_legacy`: отображаемая цитата не подготовлена. Одно поле без второго, пустая цитата, неизвестный или не связанный с evidence блок отклоняются. Поля не достраиваются автоматически, statement не подставляется вместо цитаты.

`base.check` и `profile.check` возвращают:

- `presentation_ready_claims`;
- `presentation_unready_claims`;
- `presentation_status_by_claim`, например `{"c1": "unprepared_legacy"}`.

Публичный helper `presentation_status(claim, blocks)` возвращает `ready` или `unprepared_legacy`; blocks — словарь ID→исходный блок с полем text. При предоставленной невалидной паре он выбрасывает ValueError. `ready` означает успешную механическую проверку цитаты, а не подтверждение смыслового контекста или PDF.

В техническом CSV ядра сохранён прежний аналитический statement и добавлены отдельные presentation_quote, presentation_block_id, presentation_status. У legacy quote остаётся пустым. В summary явно указаны числа подготовленных и неподготовленных цитат. Это экспорт аналитического контракта; финальный Excel должен применять отдельный строгий гейт подготовки цитат. Изменения company/yearbook экспортёров выполняет ведущий агент.

## Проверяемые правила

Цитата для вывода должна быть одной дословной непрерывной подстрокой одного блока, используемого в evidence. Склейка несоседних фрагментов не проходит проверку, даже если они по отдельности есть в источнике. Начало/конец внутри слова, составного слова или переноса `ре-\nзультате` отклоняются. Проверяется конкретное вхождение: наличие другого полного вхождения того же текста не делает его ошибочным.

Новая инструкция требует цельный контекстный фрагмент с предметом и существенными субъектом, периодом, условием/базой сравнения, если они названы в этом месте источника. Если субъект/период находится в заголовке или соседнем блоке, допустимо существующее связное предложение с внешним source context в evidence и метаданных. Отсутствующие в источнике слова в цитату не добавляются.

Несколько атомарных записей одного абзаца могут использовать один и тот же полный абзац как presentation_quote. Субъект, период, ограничения и условие не должны теряться ради краткости. Весь блок брать не обязательно. Непрерывность и границы слов проверяются программно; достаточность контекста проверяется содержательно. Новый контракт не объявляется доказательством полноты извлечения, истинности фактов или точности E/S/G.

Для исторического чтения сохранена точная прежняя инструкция в previous_prompt/esg_agent_v3_1.md; её SHA23de9bbe99f2f4ed9e08eaa112df4fd358911139c40689f28b6a002c1a3128dc совпал с исходным аудитом. ## Доработка принятых legacy-партий

По дополнительному поручению изменена только `process` canonical worker и его `test_worker_extraction.py`. Root отдельно перенёс65 аналитических партий в новую prompt revision; их наличие в accepted раньше мешало подготовке presentation-пары, поскольку process пропускал существующие файлы.

Теперь принятая партия с `presentation_unready_claims>0` выбирается наравне с отсутствующей в том же лимите. До вызова модели исходный accepted архивируется побайтово в `presentation_revisions/<batch>/<run>/previous_accepted.json` и сверяется по SHA. Модель получает previous_analytical_response.json и тот же точный проектный prompt/batch/policy/taxonomy с ограничением только добавить два presentation-поля и при необходимости обновить reviewer.

Сравнивается полная структурная проекция ответа до и после проверки: сохраняются все исходные claims, их порядок, ID, statement/evidence, значения, тип/E/S/G/decision, coverage и неизвестные дополнительные поля. Допускаются только presentation_quote/presentation_block_id и reviewer; ранее существовавшие presentation-поля также защищены от изменения. Для legacy используется строгий profile.check **без нормализующего review**, чтобы автоматически не менять старые значения или coverage. Новое извлечение сохраняет прежний review и добавленный ведущим строгий гейт обязательной presentation-пары.

На успехе сохраняются accepted_revision.json и provenance.json с originalSHA/newSHA; проверяется неизменность SHA текущего accepted с начала доработки, после чего выполняется atomic replace. При отказе старый accepted остаётся на месте; обе невалидные попытки и причины сохраняются прежним механизмом validation_attempts. Невалидный исходный accepted не превращается в фиктивно принятый ответ. Реальная модель этим исполнителем не вызывалась.

**6/6 extraction-worker tests**:4 прежних и2 новых. Новый успешный сценарий проверяет точный байтовый архив, SHA, добавление только пары и сохранение неизвестной metadata/coverage. Второй сценарий отдельно пробует подмену класса и удаление claim: оба отклоняются после ограниченного повтора, старый accepted побайтово неизменён, новой принятой версии нет. Полный лог — legacy-repair-tests.log. API статуса и search_claim не менялись; выбор отчёта по числу неподготовленных цитат выполняется контроллером ведущего агента.
