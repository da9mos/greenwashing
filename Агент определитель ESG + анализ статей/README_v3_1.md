# Агент ESG: научно обоснованный профиль3.1

18.11.2026. [Методика и определения](Методика_выявления_ESG_v3_1.md) · [Инструкция модели](agent/esg_agent_v3_1.md) · [Правила и источники](agent/decision_rules_v3_1.json) · [21 тема](agent/taxonomy_v3_1.csv).

Сначала прочитайте методику: она объясняет, что является ESG-высказыванием, границы E/S/G, разницу предмета и действующего лица, научные основания и выбранные проектом правила. Полный реестр включает показатели, отрицательные результаты и декларации. Поиск и E/S/G отделены от проверки истинности.

## Запуск

Распакуйте весь комплект. Из его корня:

```sh
python scripts/esg_agent_v3_1.py prepare report.md --report-id GAZP-2023-ЭО --out work/GAZP-2023-ЭО
python scripts/esg_agent_v3_1.py check --work work/GAZP-2023-ЭО responses/GAZP-2023-ЭО_b0001.json
python scripts/esg_agent_v3_1.py export --work work/GAZP-2023-ЭО --responses responses/*.json --out exports/GAZP-2023-ЭО
```

В Git-репозитории перед путями `scripts/`, `agent/`, `examples/` добавляется имя папки `Агент определитель ESG + анализ статей/`. Для прогона по исходникам проекта используйте pages_v4; для таблиц и битых фрагментов всё равно нужна сверка по PDF.

Модель получает новую инструкцию, справочник правил и конкретную партию; ответы сохраняет отдельно. Скрипт не вызывает модель, не ищет факты в интернете и не использует ключ API. Размер партии по умолчанию4 страницы и соседний контекст; `--pages-per-batch` меняет его без обрезки текста. Служебное вступление MD сохраняется отдельно и не приписывается физической странице.

## Что требуется в результате модели

Для каждого заявления: цитаты, тип, основная буква и тема, числовой контекст, а также decision с субъектом, пропозицией, ESG-объектом, правилом включения и классификации, ключами источников, дополнительными буквами и статусом неоднозначности. Для исключённого блока нужно правило исключения; неизвестное остаётся pending.

Ссылки decision — основания методики, не доказательства корпоративного факта. Скрипт проверяет их наличие и согласованность; истинность объяснения остаётся задачей независимой смысловой проверки. Итоговые CSV содержат эти основания рядом с заявлением, JSON хранит все цитаты.

Незавершённые блоки/изображения/числовой контекст или неоднозначная буква блокируют обычный экспорт. `--allow-partial` создаёт только черновик `_draft`. Недостающие партии не разрешаются даже этим флагом.

## Проверки и границы

- 63 теста:18 прежнего определителяv2,27 контрактаv3,18 нового профиля3.1. Это тесты программной механики.
- Реальный MD Газпрома2023:84 страницы,1237 блоков,21 партия подготовлены и привязаны к хешам методики/таксономии. Смысловое извлечение всех блоков не выполнено.
- `examples/profile3_1/source.md` и `response.json` — шесть искусственных блоков для демонстрации: E, S, G, G+E+S, неопределённая самопохвала и обычная выручка. Это авторский разбор Codex, не независимый эталон и не оценка точности.
- Полнота и точность смыслового извлечения3.1 не измерены. Старые метрикиv2 на него не переносятся.

## Проверка примера после распаковки

```sh
python scripts/esg_agent_v3_1.py prepare examples/profile3_1/source.md --report-id DEMO-2024 --out example_work --pages-per-batch 1
python scripts/esg_agent_v3_1.py check --work example_work examples/profile3_1/response.json
python scripts/esg_agent_v3_1.py export --work example_work --responses examples/profile3_1/response.json --out example_export --allow-partial
```

Ожидается4 заявления,1 pending-блок,1 исключение. Без флага экспорт отклоняется. Изображение/таблица без установленного контекста не считаются обработанными только по факту существования файла.

Контракт хранения JSON остаётся `esg-extraction-3.0`, методический профиль отдельно `decision_profile_version=3.1`. Скрипт3.1 использует неизменённый `esg_agent_v3.py`, поэтому оба файла нужны. Схема и старая версия сохранены для воспроизводимости.
