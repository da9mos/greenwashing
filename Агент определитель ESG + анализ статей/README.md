# Агент определитель ESG + анализ статей

**Дополнительный профиль полного сбора v3 (18.11.2026):** [инструкция запуска](README_v3.md). Включает показатели и таблицы, реестр всех блоков и отдельный тип заявления. Описанные ниже метрики относятся только к прежнему v2. Профиль v3 не заменяет командный кодбук и требует новой оценки качества.

*17.11.2026. Агент читает любой отчёт об устойчивом развитии (годовой, интегрированный, экологический, ESG-отчёт любой компании и отрасли). Для каждого предложения он решает, ESG-заявление это или нет, и ставит букву E, S или G, тему, вторую букву (если есть), уверенность и коротко пишет суть. Агент построен на разборе научных статей и стандартов (документ в этой папке) и на кодбуке проекта v4.*

## Как агент решает (коротко)

1. **Заявление или нет.** Заявление — мысль компании о самой себе по природе, людям или собственному управлению, которую можно проверить: результат, обязательство или декларация. Не заявления: голые объёмы без сравнения, методики, заголовки и таблицы, слова заверителя, финансовые данные, обрывки, общие слова без ESG-предмета.
2. **Буква по предмету.** Что меняется, меряется или охраняется: природа → E, люди → S, устройство самой компании → G. Инструмент (политика, комитет, ISO, обучение, KPI) букву не меняет: ISO 14001 → E, ISO 45001 → S, обучение антикоррупции → G. Это правило подтверждают Edmans (2023), ESRS, MSCI, SASB, GRI, Банк России и Минэкономразвития (раздел 5 документа по статьям).
3. **Тема** — строго из списка своей буквы; спорные случаи решают правила Т1–Т24 (по кодбуку v4).
4. **Вторая буква** (`block2`) — если второй предмет назван прямо; **уверенность** — высокая, средняя или низкая.

## Как запускать в проекте (без API-ключа)

Работа идёт так же, как остальной конвейер (`00_общий_план/Конвейер_без_API.md`). Скрипт к модели не обращается. Размечает Claude в потоке проекта, партиями.

**Шаг 1. Подготовить партии** (из корня репозитория):

```
python "Агент определитель ESG + анализ статей/scripts/esg_agent.py" prepare 03_итерация_3_пайплайн/data/pages_v4/NORN-2024-ОУР.jsonl --report-id NORN-2024-ОУР
```

- Источник: PDF (нужен `pymupdf`), TXT (страницы через `\f` или строки `=== стр. N ===`) или страницы проекта `data/pages_v4/*.jsonl`.
- `--pages 40-55` — только эти страницы; `--batch-size 40` — размер партии.
- `--esg-filter` — оставить только предложения с ESG-словами. Это быстрее, но на эталоне теряет 13 из 465 заявлений (2,8%) и убирает только 56 из 346 незаявлений, поэтому по умолчанию выключено. Фильтр шума (короткие строки, строки из цифр) не потерял ни одного заявления.
- Результат: `work/<код>/sentences.jsonl` и партии `work/<код>/batches/<код>_b001.jsonl …`.

**Шаг 2. Разметить партии в потоке проекта.** Координатор открывает поток с инструкцией:

```
Этап: esg_agent. Отчёт: NORN-2024-ОУР. Промпт: «Агент определитель ESG + анализ статей/agent/esg_agent_v2.md».
1. Прочитай промпт целиком. Не пересказывай и не меняй его.
2. Партии лежат в «Агент определитель ESG + анализ статей/work/NORN-2024-ОУР/batches/». Бери по порядку те,
   на которые ещё нет ответа в llm/esg_v2/.
3. На каждую партию: ответь строго JSON-массивом из промпта и запиши ответ в
   «Агент определитель ESG + анализ статей/llm/esg_v2/<имя партии>.json». Существующие файлы не перезаписывай.
4. Проверь: python ".../scripts/esg_agent.py" check <партия.jsonl> <ответ.json>.
   Ошибку формата исправь, содержание не меняй.
5. Запиши журнал: python ".../scripts/esg_agent.py" manifest <партия.jsonl> <ответ.json> --model <модель> --thread "<название потока>".
6. В конце: сколько партий готово, сколько заявлений E, S, G, что требует внимания (низкая уверенность, ошибки формата).
Ничего не выдумывай: суть заявления — только по тексту предложения.
```

**Шаг 3. Собрать таблицу отчёта:**

```
python ".../scripts/esg_agent.py" export NORN-2024-ОУР --version v2
```

Получится `work/NORN-2024-ОУР/NORN-2024-ОУР_esg_v2.csv` (CSV, `;`, UTF-8 с BOM): `sentence_id; report_id; page; block; topic; block2; confidence; essence; sentence; reason; rule; agent_version` и сводка по буквам и темам `…_сводка_v2.md`. Скрипт предупредит, если не все партии размечены.

**Второй разметчик.** По правилам проекта второй разметчик — другая модель с другим промптом, спорное решает Егор Д. Для агента это значит: тот же `prepare`, ответы второй модели в отдельную папку (например `llm/esg_v2_b/`), сравнение — тем же `evaluate`, если положить ответы одной модели как эталон, или простым сравнением двух CSV.

**Переход на API (если появится ключ).** Менять ничего, кроме исполнителя, не нужно: промпт — системное сообщение, строки партии — сообщение пользователя, ответ модели сохраняется в тот же `llm/esg_v2/<партия>.json`, дальше те же `check`, `manifest`, `export`. Цикл по партиям — 10–15 строк кода вокруг уже готовых функций `read_jsonl` и `validate`.

## Как проверить агента заново

```
python ".../scripts/esg_agent.py" make-eval working     # или heldout; партии уже лежат в eval/batches/
python ".../scripts/esg_agent.py" evaluate llm/eval_v2 --prefix heldout_ --report eval/результат.md --errors eval/ошибки.csv
python -m pytest "Агент определитель ESG + анализ статей/tests" -q
```

Новая версия промпта — новый файл `agent/esg_agent_v3.md` и новые папки `llm/eval_v3/`, `llm/esg_v3/`. Старые ответы не перезаписываются.

## Насколько агент точен

Проверка на эталоне проекта (811 предложений, 465 заявлений; `03_итерация_3_пайплайн/data/out/gold_extract_text_v4.csv`). Рабочая часть — для поиска ошибок, отложенная — для честной оценки.

| Что сравниваем | v1, рабочая часть (506) | v2, отложенная часть (305) |
|---|---|---|
| ESG-заявление или нет | 92,5% (каппа 0,85) | 89,5% (каппа 0,79) |
| Буква E/S/G | 95,2% (каппа 0,92) | **99,4% (каппа 0,99)** |
| Буква и тема | 85,7% | 88,5% |

На предложениях, где оба разметчика эталона сразу совпали (264 из 305), v2 даёт: заявление или нет 95,5%, буква 100%, буква и тема 92,6%. Расхождения собраны там, где спорили и сами разметчики. Подробно: `eval/разбор_ошибок_v1.md`.

## Ограничения и известные ошибки

- **Склеенные заголовки, таблицы и инфографика.** Главный источник ошибок «заявление или нет»: внутри склейки бывает цель или результат («-30% снижение удельных выбросов»), и агент может её пропустить. Тексты с таблицами в проекте пока не разобраны (см. `data/text_v3/README.md`).
- **Темы в пограничных зонах:** коррупционные риски (этика или управление рисками), Глобальный договор ООН (раскрытие или «другое»), обучение по охране труда (безопасность труда или обучение), кадровый резерв. Кандидаты в v3 перечислены в разборе ошибок; сам эталон здесь местами непоследователен, решать Егору Д.
- **Разрезанные предложения.** Скрипт больше не режет на «тыс.», «млн», «см.», «с. 45», но может разрезать на «г.» в конце фразы («в 2023 г. Компания…»). Агент видит соседние предложения в `context`.
- **Агент не проверяет правдивость.** Он только находит и сортирует заявления. Сверка с фактами и риск-сигналы — следующие этапы конвейера.
- **Проверяла та же модель, что писала промпт** (Claude в этом потоке). Независимая проверка — второй моделью с другим промптом по правилам проекта.
- **Отчёты вне выборки** (банки, ритейл, ИТ, транспорт) покрыты общими правилами в промпте, но на эталоне не проверялись: эталон собран по 30 компаниям проекта.
- **Четыре предложения по кодбуку** из разбора статей (совет директоров + климат, персональные данные, поставщики, поле block2) ждут решения Григория. Агент до решения следует кодбуку v4.
