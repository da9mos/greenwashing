# Детектор гринвошинга (Сбер, практикум ESG, проект 2)

Сравниваем ESG-заявления 30 российских компаний (отчёты 2023–2025, блоки E, S и G) с цифрами из тех же отчётов и с внешними фактами: штрафами, авариями, несчастными случаями, судами, новостями. Каждое заявление получает класс «подтверждено / декларативно / противоречит фактам», из классов складывается индекс риска компании. Это риск-сигнал для внутренней аналитики банка, а не обвинение.

Команда: Никита Чукреев, Егор Дровосеков, Григорий Утямишев, Георгий Разинкин, Егор Коровкин. Работу с текстом (поиск заявлений, разметку, классы) делают модели Claude партиями в потоках проекта на claude.ai, скрипты Python делают механику и собирают таблицы. API-ключ не нужен.

*Репозиторий — копия библиотеки проекта «Сбер гринвошинг» на claude.ai на 12.11.2026. Главная копия по-прежнему библиотека проекта; сюда выгружаем после каждого этапа.*

## Что уже сделано: эталон поиска заявлений (задача Григория, критерии 4 и 5)

Эталон нужен, чтобы измерить, сколько заявлений находит и сколько пропускает поиск Георгия. Для этого в отрывках размечено всё подряд, каждое предложение.

- **Итог:** 811 предложений из 130 отрывков (74 отчёта, все 30 компаний), из них **465 заявлений**: 350 результатов, 71 декларация, **41 обязательство** (цели и сроки отдельно добраны, в основной выборке их было мало).
- **Как размечено:** два разметчика — две разные модели Claude с разными промптами (A и B), каждый не видит ответов другого. Где они разошлись, решал третий проход (C), спорное решил Егор Д. (14.11.2026). Использование моделей вместо людей согласовано.
- **Согласие A и B:** 95% по вопросу «заявление или нет» (каппа Коэна 0,89), 95% по типу (0,86), 98% по блоку E/S/G (0,97), 90% по теме (0,89). Полная сводка: [data/gold_extract/agreement.md](03_итерация_3_пайплайн/data/gold_extract/agreement.md).
- **Деление:** 506 предложений рабочие (на них правили инструкцию и промпты), 305 отложенные (их не видел никто при правке; на них потом честно меряем поиск Георгия).
- **Инструкция по разметке** прошла версии v0 → v3; действует v3.

### Как читать эталон (`data/out/gold_extract.csv`)

Одна строка — одно предложение отчёта.

| Колонки | Что значат |
|---|---|
| `sentence_id`, `fragment_id`, `report_id`, `company_id`, `year`, `page` | откуда предложение; `page` — номер страницы в PDF (у Мосводоканала 2023 и 2025 — печатный номер) |
| `split` | `рабочий` или `отложенный` (отложенные не трогать при правке промптов) |
| `sample_part` | часть выборки: `ESG-кусок`, `случайный`, `цели и сроки` |
| `sentence` | текст предложения дословно |
| `A_…`, `B_…` | ответы разметчиков A и B |
| `agree` | совпали ли A и B |
| **`final_is_claim`, `final_type`, `final_esg_block`, `final_topic`, `final_has_number`, `final_has_deadline`** | **итоговая разметка — именно её и используем** |
| `resolved_by` | `совпало` / `третий проход` / `Егор Д.` / `не решено` |
| `resolution_note` | пометка к решению Егора Д. |
| `human_check` | `да` — предложение проверил Егор Д. (44 предложения, 14.11.2026) |

Значений `НА ПРОВЕРКУ` больше нет: все спорные решил Егор Д. (решения в [resolutions.csv](03_итерация_3_пайплайн/data/gold_extract/resolutions.csv)).

## Тексты отчётов

Тексты всех 92 отчётов лежат в репозитории (около 190 МБ вместе с кусками):

- **`03_итерация_3_пайплайн/data/pages/<код_отчёта>.jsonl`** — основной вариант. Одна строка — одна страница: `{"report_id": "NORN-2024-ОУР", "page": 1, "text": "…", "n_chars": 108}`. `page` — номер страницы в PDF, по нему ставим ссылку на цитату.
- **`03_итерация_3_пайплайн/data/chunks/<код_отчёта>.jsonl`** — те же тексты кусками ~1 500 знаков (`chunk_id`, `report_id`, `page`, `text`); кусок не переходит через границу страницы. С ними работают партии для моделей.
- **`data/pages/quality.csv`** — качество текста по каждому отчёту: 88 «хорошо», 4 «проверить» (причина в колонке `note`; у Мосводоканала 2023 и 2025 страницы восстановлены по печатным номерам).

Как открыть: на GitHub файл открывается прямо в браузере (очень длинные файлы GitHub показывает только по кнопке Raw). На компьютере — любым текстовым редактором (Блокнот, VS Code) или в Python:

```python
import json
pages = [json.loads(line) for line in open("03_итерация_3_пайплайн/data/pages/NORN-2024-ОУР.jsonl", encoding="utf-8")]
print(pages[9]["page"], pages[9]["text"][:500])
```

**Вне репозитория остаются только PDF** (около 1,8 ГБ: GitHub не рассчитан на такой объём) и архив КАМАЗа 2025. Их берём на Google Drive по `drive_id` из [reports.csv](01_итерация_1_сбор_данных/выборка_30/reports.csv) или скачиваем заново: из папки `03_итерация_3_пайплайн` выполнить `pip install -r requirements.txt` и `python src/download.py`. Тексты из PDF получаются командами `python -I src/parse.py` и `python src/chunk.py` (готовые файлы они не перезаписывают). Также не выгружены устаревшие тексты первой версии разбора (`data/pages_v0_sort/`, перемешанные колонки) и загрузки из чатов.

## Как пересобрать эталон из сохранённых ответов

Модель для этого не нужна, все ответы лежат в `llm/`. Из папки `03_итерация_3_пайплайн`:

```
python src/check_llm.py --version v3          # проверка ответов и журнала
python src/agreement_extract.py --version v3  # gold_extract.csv, расхождения, каппа
python src/build_review_list.py --version v3  # список для проверки Егором Д.
```

Для сборки эталона тексты отчётов не нужны: предложения уже лежат в `data/gold_extract/sentences*.jsonl`. Отбор отрывков заново (`select_gold_fragments.py`, `select_gold_commitments.py`) берёт куски из `data/chunks/`.
