## Как собран датасет

- Основа выборки — 928 исходных заявлений и 46 дополнений. Для расчёта квот использован запас в исходном наборе. Из каждой компании включено по одной записи, остальные места распределены пропорционально весам 1, 0,75 и 0,5 с учётом доступного числа заявлений. Вес 0,5 у трёх компаний с более слабыми раскрытиями.
- Внутри каждой квоты в приоритете заявления с готовым сравнением целей, связью с внешним фактом или точно совпавшей ручной проверкой извлечения. Остальные отобраны по детерминированному порядку SHA-256 от `claim_id`. Набор предназначен для разметки и проверки сценариев. При оценке распространённости классов такое распределение нужно учитывать.
- 49 сопоставлений целей из рабочей книги v3 связаны с 48 заявлениями. У 24 строк есть сопоставимый опорный факт и ссылка. У 16 строк указан предварительный класс «подтверждено» по выполненным целям. Опубликованные выводы по невыполненным целям оставлены в поле динамики. Для остальных строк класс ожидает проверки. Уверенность при извлечении сохранена для 454 строк.
- Ссылки в поле «источник заявления» ведут на исходный отчёт. «Источник факта» содержит страницы, по которым удалось сопоставить динамику. «Контекст внешних фактов» содержит идентификаторы записей, связанных по теме или процедуре. Сам по себе такой контекст даёт направление для проверки.

## Покрытие базы внешних фактов

В реестре записаны события 2023–2025 годов и стадии более ранних дел, которые рассматривались в этот период. Дата относится к стадии, указанной в записи. Документы, перепечатки и сообщения СМИ различаются по типу источника. Для финальной версии нужно расширить покрытие компаний и сверить новые события с заявлениями по периоду, показателю и периметру.

В реестр добавлены судебные акты и сообщение об инциденте по итогам [пилотной проверки по Газпрому](https://github.com/da9mos/greenwashing/blob/7c84b8079f3f33ede57ab80b5638f915999a20a0/Основной_проект/09_Годовые_книги_и_цитаты/README.md). Для каждого события указано юрлицо, к которому оно относится.

## Как завершить разметку

1. Откройте исходный отчёт на указанной странице и проверьте точность цитаты и тип заявления.
2. Для проверки класса сопоставьте тот же показатель, период и периметр. Запишите опорный факт и ссылку на страницу или документ. Если для проверяемого заявления данных недостаточно, укажите причину в комментарии. Рабочие критерии классов описаны ниже в методике.
3. Заполните имя проверявшего и дату. Перенесите согласованные метки в датасет по `claim_id`. Сверьте число завершённых записей.

В отдельном эталоне по извлечению вручную проверено 44 предложения, среди них 32 заявления. С новым датасетом точно совпало одно заявление. В поле «ручная проверка извлечения» сохранена ссылка по идентификатору этого предложения. Ручной эталон классов для 150 заявлений требуется заполнить.
