## 1. Суть задачи в одном абзаце

Гринвошинг — это **разрыв между тем, что компания говорит, и тем, что она делает** (Delmas & Burbano, 2011: «говорит / делает»). В проекте мы не доказываем умысел, а **измеряем этот разрыв**. Каждое ESG-заявление из отчёта проверяем по двум независимым источникам: (а) по цифрам из того же и следующих отчётов компании, (б) по внешним событиям: штрафам, предписаниям, авариям, судам, СМИ. По итогам у заявления один из трёх классов: *подтверждено*, *декларативно* (проверить нечем) или *противоречит фактам*. Классы складываются в **индекс риска гринвошинга компании**. Это внутренний риск-сигнал для клиентского менеджера банка, не публичное обвинение.

**Охват: ESG целиком, а не только экология.** По каждой из 30 компаний выборки («Итоговая выборка — 30 компаний», отчёты 2023–2025) смотрим все три блока: E (экология), S (люди и общество: охрана труда, персонал, местные сообщества) и G (управление: совет директоров, антикоррупция, раскрытие). Термин «гринвошинг» в названии проекта понимаем широко, как ESG-washing.

Банку это нужно, потому что CIB выдаёт ESG-кредиты и SLL. Если банк поверит декларациям клиента, он получит репутационный риск «зелёного дисконта ни за что». Детектор показывает, каким заявлениям клиента можно верить, а какие требуют вопросов.

## 2. Что жёстко требует ТЗ (слайд 13), и где подвохи

| № | Требование | Подвох / что учесть заранее |
|---|---|---|
| 1 | ≥20 компаний, ≥2 годовых отчёта на компанию | Выборка — папка «Итоговая выборка — 30 компаний» (6 отраслей), работаем по всем 30. Сканы (Калининградский янтарный комбинат, SPLAT), «Т Плюс 2024» (текст не извлекается) и архивы .rar/.zip требуют OCR или ручной работы, поэтому в основную выборку их лучше не брать |
| 2 | ≥500 заявлений с типом и блоком E/S/G | Извлекать 700–800 с квотами по типам и годам, иначе не хватит пар «обещание 2023 → результат 2025» |
| 3 | Внешние факты из ≥3 типов источников, с датой и ссылкой | Штрафы выписывают дочерним юрлицам, поэтому искать надо по ИНН, а не по бренду |
| 4 | ≥150 заявлений размечены двумя аннотаторами, κ Коэна ≥ 0,6 | Из-за класса «декларативно» каппа обычно проседает. Нужна чёткая инструкция и пилот на 30–50 фрагментах |
| 5 | Макро-F1 ≥ 0,70 плюс отдельно P/R для «противоречит» | **Главный подвох.** «Противоречит» — редкий класс: при случайной выборке эталона в нём окажется 5–10 примеров, и F1 по нему будет шумным. Эталон нужно **стратифицировать**, то есть специально добрать заявления по темам, где у компании есть внешние факты |
| 6 | Индекс с формулой и сравнение с АКРА / «Эксперт РА» | При n≈20–30 корреляция маломощна, поэтому нужен доверительный интервал. Связь может оказаться нулевой или даже положительной (см. гипотезу «парадокс прозрачности», раздел 5) |
| 7 | ≥3 кейса «декларация — факт» с полной цепочкой | Кейсы закладываем уже в итерации 2: сквозной пример на компании с богатым материалом (например, Норникель, ММК, ФосАгро), с заявлениями из E, S и G |
| 8 | Ограничения: галлюцинации, неполнота, умысел и ошибка, правовые риски | Отдельная глава; формулировки нейтральные |
| 9 | Воспроизводимость | API не используем, поэтому `temperature = 0` не задать. Фиксируем версии промптов, сохраняем каждый ответ модели по партиям с хэшами входа и промпта и моделью в журнале; все таблицы пересобираются из ответов одной командой без модели; устойчивость меряем повторным прогоном части партий. Ведём requirements.txt и README |

Плюс межкомандное требование (слайд 19): единая схема классов и формат датасета с командой Арины Ким. Их нужно согласовать на первой контрольной точке.

Green Claims Directive: в июне 2025 Еврокомиссия объявила о намерении её отозвать, но [формально не отозвала](https://www.lw.com/en/insights/european-commission-announces-intention-to-withdraw-eu-green-claims-directive-proposal), статус неопределённый. *В таблицу литературы итерации 2 стоит внести это уточнение.*

## 4. Архитектура решения

```
PDF-отчёты (30 комп. × 3 года)
   │ 1. Парсинг: PyMuPDF/pdfplumber, OCR (Tesseract rus) для сканов; текст+номер страницы; таблицы отдельно
   ▼
Чанки 1–2 тыс. символов (company, year, page)
   │ 2. Фильтр: словарь ESG-лексики (E, S, G) + эмбеддинги (дешёвый предотбор)
   ▼
LLM-извлечение заявлений → JSON (type, esg_block, topic, metric, value, unit, base_year, target_year)
   │   проверка: цитата дословно есть в чанке (rapidfuzz ≥ 95), иначе отбрасываем
   ▼
claims ──────────────┬───────────────────────────────┐
                     │ 3a. metrics_dynamics          │ 3b. external_facts
                     │ таблицы показателей / GRI-    │ ЕРКНМ, РПН, РТН, kad.arbitr,
                     │ индекс по 3 годам; пары       │ sudact, Роструд, ФАС, ЦБ, СМИ,
                     │ «обещание N → факт N+1, N+2»  │ Violation Tracker, разделы отчётов
                     │                               │ о плате НВОС, травматизме, штрафах
                     ▼                               ▼
              4. Сопоставление по ключам (company_id, year, topic) + поиск доказательств
                     ▼
              5. LLM-судья: заявление + доказательства → класс + опорный факт + обоснование
                 (self-consistency: 3 прогона, при расхождении → «на ручную проверку»)
                     ▼
              6. Флаги риска + индекс компании → сравнение с рейтингами → кейсы → дашборд
```

**Где работает модель (решение 12.11.2026).** Шаги с LLM (извлечение, LLM-судья, разметка эталона, чтение таблиц показателей) выполняет Claude в потоках проекта на claude.ai, без API-ключа: скрипт готовит партии, поток пишет ответ JSON в `llm/<этап>/<версия>/`, скрипт проверяет и собирает таблицы. Парсинг, фильтр, проверка цитат, сопоставление, флаги, метрики и индекс — скрипты без модели. Self-consistency на шаге 5 — два прохода в разных потоках, при расхождении третий и ручная проверка. Подробно в [Конвейер_без_API.md](Конвейер_без_API.md).

**Ключевой принцип: LLM не придумывает факты, а выбирает их.** На шаге 5 модель видит только найденные доказательства и обязана сослаться на `fact_id` или номер страницы. Если ссылки нет, вердикт «декларативно».

**Выбор модели.** Изначально задумано две модели в сравнении: одна сильная зарубежная (Claude / GPT) и **GigaChat** (Сбер). Доступа к GigaChat и к API нет, поэтому сейчас сравниваем две модели Claude в отдельных потоках; если GigaChat появится, добавим его как третью. Для заказчика из Сбербанка это прямой плюс: данные остаются в РФ, и можно показать, насколько отечественная модель уступает или не уступает. Сравнение двух моделей на эталоне — готовый раздел отчёта.

## 5. Как сделать проект интересным и креативным (без потери строгости)

1. **«Обещания с истёкшим сроком»: самый сильный тип проверки.** Многие цели в отчётах 2023 года поставлены «к 2024/2025». В отчётах за 2025 год их судьбу можно проверить **окончательно**, без экстраполяции: *выполнено / не выполнено / тихо исчезло / перенесено*. Для таких целей отдельная подтаблица и график «кладбище обещаний».

2. **Автоматическая проверка пересчётов (restatement).** Одно и то же значение (например, выбросы 2023 года) публикуется в отчётах за 2023, 2024 и 2025 годы. Если цифра за тот же год «поплыла», это флаг смены периметра или базы. Проверка дешёвая, полностью автоматизируемая и почти никем не делается.

3. **Флаг «удельные против абсолютных».** Компания хвалится снижением удельных выбросов на тонну продукции, а абсолютные выбросы растут. То же в блоке S: снижается частота травм (LTIFR), а число погибших растёт. Считаем это автоматически по metrics_dynamics.

4. **Индекс «конкретности» (cheap talk по Bingler).** Для каждого заявления считаем, есть ли в нём цифра, срок, базовый год, периметр и внешнее заверение (0–5). Средняя конкретность по компании — отдельная ось.

5. **Карта «говорит / делает» (матрица Delmas & Burbano).** Ось X: интенсивность и конкретность ESG-заявлений. Ось Y: фактическая результативность (динамика метрик + внешние инциденты). Четыре квадранта:
   - «молчаливо зелёные» (greenhushing),
   - «честно зелёные»,
   - **«гринвошинг»** (много говорят, мало делают),
   - «честно коричневые».

   Это главный слайд защиты, его поймут за 5 секунд.

6. **Гипотеза «парадокс прозрачности».** Рейтинги во многом награждают раскрытие (Yu, Luu, Chen 2020: ESG-washing = разрыв между оценкой раскрытия и оценкой результатов). Поэтому индекс может не коррелировать с рейтингами или коррелировать положительно: больше пишешь — больше заявлений, которые можно опровергнуть. Отрицательный результат сравнения с АКРА / «Эксперт РА» при такой гипотезе становится **содержательной находкой**, а не провалом. Её надо сформулировать заранее, до расчёта, чтобы это не выглядело подгонкой.

7. **Абляции: что даёт каждый источник.** Считаем качество классификации в трёх режимах: (а) только текст заявления, (б) + динамика из отчётов, (в) + внешние факты. Прирост F1 показывает, зачем собирать базу фактов. Это сильный аргумент для заказчика.

8. **Прототип для клиентского менеджера.** Streamlit-дашборд: выбираешь компанию и видишь индекс, позицию на карте «говорит / делает», топ-5 рискованных заявлений с цитатой, страницей и внешним фактом по ссылке. Камилла работает с металлургией, поэтому демо на защите стоит вести на металлургическом клиенте (ММК / Северсталь / НЛМК).

9. **Анализ устойчивости индекса.** Monte Carlo по весам (например, 1 000 случайных наборов весов из симплекса) → насколько стабильны ранги (τ Кендалла, доля компаний, не выходящих из топ-5). Требование «чувствительность к весам» закрывается красиво.

10. **Нейтральный язык как часть продукта.** Шаблон вывода: «Заявление X (стр. N) расходится с данными Y (источник, дата)», без слов «обман» или «ложь». Это закрывает правовой риск (защита деловой репутации) и требование слайда 11.

## 6. Методические решения, которые стоит зафиксировать сейчас

**Единица анализа.** Одно заявление = одна проверяемая мысль (составные фразы делим). Не заявления: пересказ законов, описание методик, благодарности.

**Типы** (по A3CG): обязательство (planning), результат (implemented), декларация (indeterminate).

**Классы** (по FEVER) и поле причины:
- *подтверждено*: есть опорный факт того же направления и порядка величины, противоречащих нет;
- *декларативно*: `reason ∈ {нет измеримого содержания, нет данных, срок не наступил}`;
- *противоречит*: показатель движется в обратную сторону / цель исчезла или сдвинута без объяснения / есть штраф, авария или суд по той же теме и периоду.

**Правило «та же тема и период» для внешних фактов.** Факт противоречит заявлению, только если совпадают блок и тема (E: вода / воздух / отходы / климат / биоразнообразие / земля; S: безопасность труда / персонал / сообщества; G: совет директоров / этика и антикоррупция / раскрытие), период (± 1 год) и юрлицо или объект в периметре отчёта. Без этого правила LLM станет «опровергать» любые заявления любым штрафом.

**Тяжесть внешнего факта** (`severity`, 1–3, по логике RepRisk): 1 — предписание или штраф до 1 млн ₽; 2 — штраф до 100 млн ₽, иск, локальная авария; 3 — крупная авария, иск о вреде свыше 100 млн ₽ или пострадавшие. Пороги утвердить с заказчиком.

**Индекс (доработка черновика из итерации 2):**

```
GRI_c = w1·share_contr + w2·share_decl + w3·share_unmet_commit + w4·min(1, S_ext/S_max) + w5·flags_c
```

- `flags_c` — доля сработавших флагов (restatement, удельные против абсолютных, исчезнувшая цель, нет заверения).
- **Сглаживание для малых выборок**: доли считаем с байесовским сглаживанием `(k + α)/(n + α + β)`. Иначе у компании с 4 заявлениями одно противоречие даст 25%.
- **Отраслевая нормировка**: S_ext сравниваем внутри отрасли (у нефтегаза штрафов объективно больше).
- Отчитываемся двумя вариантами весов: экспертные и равные. Плюс Monte Carlo (п. 5.9).

**Эталонная выборка (150–200 заявлений), стратифицированная:**
- ~40% — заявления по темам, где у компании есть внешний факт или ухудшение метрики (кандидаты в «противоречит»);
- ~30% — заявления с цифрами (кандидаты в «подтверждено»);
- ~30% — случайные.

В отчёте честно указываем, что выборка стратифицирована, и даём также оценку на случайной подвыборке. Размечают два аннотатора независимо: Claude с промптом A и другая модель Claude с промптом B, в разных потоках проекта, B не видит ответов A (решение от 06.11.2026, вручную никто не размечает; без API с 12.11.2026); расхождения разбирает человек (Егор Д.). Считаем κ по типам и по классам отдельно и в отчёте прямо пишем, что оба аннотатора — модели.

**Метрики:** макро-F1 и P/R по каждому классу, матрица ошибок, бутстреп-доверительные интервалы (1 000 ресэмплов). Для извлечения: полнота против эталона и точность типа. Для сравнения с рейтингами: Спирмен и Кендалл с p-value и ДИ, разбор 5 компаний с наибольшим расхождением.

**Бейзлайн**, чтобы было, с чем сравнить LLM: правила (ключевые слова + наличие цифры/срока) или TF-IDF + логистическая регрессия на эталоне. Показать «LLM vs бейзлайн» обязательно, иначе F1 = 0,72 ничего не значит.

| Тип (нужно ≥3) | Источник | Как |
